# 英雄系统 v2：玩家统一等级与占位 UI 实施方案

日期：2026-09-26。交付类型：**供其他 harness 执行的设计规格，未实施到游戏**。

用户已确认：①全部英雄使用玩家等级；②玩家通过战斗升级，新英雄立即可用；③v1 其他英雄系统方向保留；④需要无正式美术也能使用的 UI。本文件取代 v1 中五人培养、共鸣、继承、个人升级/重置等冲突规则。以下新增经验公式、补偿折算和布局尺寸是可直接实施的首版默认值，尚未经真实玩法平衡验收。

交互原型：[docs/ui/hero-system-v2.html](ui/hero-system-v2.html)。浏览器直接打开，无依赖、无联网、无游戏存档读写。原型含示例英雄、示例属性及流程，并非全部120将的最终数据；本规格是规则依据，原型是布局和交互参考。

## 1. 第一版交付目标与边界

玩家闭环：**战斗胜利 → 玩家升级 → 全部英雄同步变强 → 抽到新人直接换阵 → 用同名卡升星 → 继续挑战**。

第一版必须同时交付：统一等级、可靠战斗经验、卡关练兵、永久英雄归属、简单升星、自选券持久化、五人编队、完整 UI 和旧档迁移。以“新建账号不抽卡也能组成五人队；新抽英雄不用重新练；重复结算不重复发奖；换人不丢资产”为底线。

本轮不新增觉醒、命座、专武、技能等级币、品质进阶链、自动卖本体或收集属性。不扩大到完整装备重做、剧情/地图重做或正式立绘制作。战斗和输入的前置缺陷必须修，否则无法验收本英雄系统。地图若另一执行者已实施则接入，否则主城直接出征/练兵即可，不依赖地图方案批准。

## 2. 等级与战斗经验

### 2.1 唯一等级来源

- 新玩家 Lv.1；上限沿用200。`state.player.level` 为所有已拥有英雄唯一有效等级，`state.player.exp` 为当前等级内经验。
- 战斗计算、详情、战力、编队、招募结果、图鉴已拥有状态均通过同一 `playerLevel()` / `effectiveLevel(id)` 读取；稀有度和星级不裁切等级。
- 未拥有英雄只能预览，不能编队；详情可用当前玩家等级预览并标明“解锁后共享”。敌人等级仍由关卡定义，不能把敌人也全部改成玩家等级。
- 新抽/自选获得英雄立即使用玩家当前等级。换人不收费、无冷却；不需要“同步等级”按钮。
- 删除个人升级、连升、均衡培养、共鸣水晶、培养位、等级继承、等级重置入口。保留旧 API 时只能读取共享等级或返回明确停用错误，不能隐蔽修改个人等级。
- 经验只能由有效战斗胜利结算产生。挂机、离线、任务领取、商店购买、广告奖励不直接发玩家经验。练兵也是完整战斗，不是领经验按钮。
- 战斗开始时快照玩家等级/属性/阵容/敌人/随机种子。战后升级只影响下一场，不能中途改变正在计算的单位。

### 2.2 首版公式

从 L 升到 L+1：`needXP(L) = 100 + 20 × (L − 1)`，L=1…199。

战斗参考等级 `D`：战役/塔采用关卡配置的参考等级；演武采用开战时敌队等级均值向下取整；练兵为 `max(1, 开战玩家等级−2)`。均在开战时冻结。

`baseXP(D) = 40 + 10 × D`。最终经验向下取整，最低0。

| 模式 | 胜利经验 | 次数和说明 |
| --- | --- | --- |
| 战役首通 | `3 × baseXP(D)` | 只允许当前下一关获得首通；3倍是总额，不是再额外加3倍 |
| 战役重打 | `baseXP(D) × clamp(D / 开战玩家等级, 0.2, 1)` | 已通关可重打；不再得首通宝箱；无经验日上限 |
| 塔首通 | `2 × baseXP(D)` | 只首通发经验；重打已通层不发经验 |
| 演武胜利 | `baseXP(D)` | 沿用现有每日挑战次数，不额外做首胜经验；开战预留次数，避免退出刷对手 |
| 练兵胜利 | `0.6 × baseXP(D)` | 无次数限制，只给经验，不给铜钱/装备/首通奖励 |
| 失败、撤退、无效战斗 | 0 | 不推进关卡/塔层；演武失败的既有积分/代币另按规则结算 |

升级循环：经验加到账户后，反复扣当前升级所需值并提升等级，支持一次跨多级。到200级将等级内经验归0，显示“已达等级上限”，不暗存无限经验，不转换其他资源。200级结算仍可得正常铜钱/物品。

广告翻倍只作用于允许翻倍的铜钱/物品，**不翻倍玩家经验**；战斗加速/跳过不改变经验或胜负。同一战斗不能反复看广告反复领奖。

已计算的经验节奏（仅按每关胜利一次；没有证明这些关都能打赢）：

| 已首通关数 | 敌方参考等级 | 结算后玩家等级 | 等级内经验 |
| --- | ---: | ---: | ---: |
| 1 | 1 | 2 | 50 / 120 |
| 10 | 15 | 16 | 60 / 400 |
| 20 | 31 | 31 | 420 / 700 |
| 60 | 95 | 93 | 1,040 / 1,940 |
| 120 | 191 | 186 | 1,820 / 3,800 |

表按当前战役参考等级 `round(1+1.6×(关号−1))` 与上述公式计算。参数集中于 `utils/config.js`，不要硬编码到界面。

### 2.3 卡关出口：练兵

主城“出征”旁提供44px以上的“练兵”按钮，从第一场战斗前即可进入。进入前显示敌方参考等级、胜利经验和“不消耗次数”。

首版练兵队使用现有 N 卡 `liaohua / mengda / masu`，3人、0星、无装备，参考等级 D，额外属性倍率默认0.6；编排为2前排1后排。使用正常战斗引擎；失败仍零经验。默认五人新手队在1级多种随机种子下必须能稳定取胜；若不满足应降低练兵系数，不能伪造胜利或失败发经验。

允许重打已通主线；没有地图时在主城挑战面板附“重战上一关”（cleared≥1才出现）。当前关失败后提供“调整阵容 / 练兵 / 再战”。正常再战使用新战斗ID；不限制正常练兵次数，不添加体力系统。

### 2.4 关卡数值必须同步收敛

当前敌人除等级外还叠战役 `1.05^(关号−1)`、塔 `1.075^(层号−1)`。战役120关额外倍率约332.30，统一等级无法填补差距。

首版测试基线：**移除两者的指数额外倍率，普通基础倍率设1**；战役保留原Boss1.25及原普通单位0.92规则，塔保留原普通0.9/Boss1.2规则。关卡敌级沿用现有线性公式。只删除额外指数，不删除英雄等级成长、星级、技能或阵营效果。

此举是配套平衡起点，不能当作全关卡已平衡。须扫描首章及后续1–120关，记录等级/星级/装备/阵容/种子/胜率/战斗时长，定位断崖和无解关；调参集中配置，不能加“玩家战力到线就必胜”的伪战斗。首版发布至少逐关验收前20关；若保留120关全部可达，则120关都要有可解释的通关样本与成长路径，不能只验前20关就声称全部内容可玩。

## 3. 兵书退休，经验与资源分离

现有 `res.exp` 名为兵书，挂机/商店/任务等均有来源。**禁止将 res.exp 直接更名为 player.exp**，否则用户“战斗升级”的决定不成立。

首版不再使用兵书；`res` 中保留铜钱、元宝、招募令、演武令、通用英雄碎片。新增玩家经验仅存 `player.exp`，不能经通用 `applyReward({exp:...})` 发放。

来源处置默认如下：

| 旧位置 | 新规则 |
| --- | --- |
| 新号60,000铜钱+40,000兵书 | 改100,000铜钱；经验0；其余赠送不变 |
| 旧战役奖励中的兵书 | 按旧数值1:1并入铜钱；另按第2节产生玩家经验 |
| 旧任务/活跃/宝箱中兵书 | 同样折铜钱；不产生玩家经验 |
| 挂机与快速收获的兵书产率 | 折入铜钱产率；招募令/其他收益照旧 |
| 商店兵书商品 | 停售，移除入口；既有铜钱商品价格/限购不变，不凭空增加第二份限购 |
| 旧“提升英雄等级”日常任务 | 替换为“战斗胜利1次”，任务活跃值/原奖励等值保留；练兵可完成，满级玩家可做 |
| 展示与飘字 | 兵书全部移除；等级进度统一叫“玩家经验” |

1:1是迁移与第一轮联调默认，避免旧资产直接消失；不是已验证经济平衡。取消升级铜钱消耗后，需记录首章/第20关/第60关的铜钱收入、升星与装备支出，若积累过快再统一调整未来投放；不要通过暗扣旧补偿修正。广告不得把已入账旧兵书再转换一次。

`q_levelup`旧领取记录迁移到新任务对应记录：已领维持已领，已完成未领维持可领；不能因改ID重复领当天活跃奖励。已有战斗胜利次数可帮助完成新任务，沿用旧活跃总结构。

## 4. 英雄获得、升星、同名卡、自选

### 4.1 保留与简化

- 保留120将、魏蜀吴群、五职业、固定概率SSR2%/SR10%/R28%/N60%、无保底。十连=十次独立抽取。目标标记不改概率。
- 首次获得：永久解锁本体，0星、同名卡0；重复获得：同名卡+1。同队不能两个同ID英雄。
- 英雄本体不能遣散；装备不会因兑换同名卡而删除。星级、装备、同名卡属于个人，玩家等级属于账号。
- 普攻+必杀+被动；0星就具有完整核心功能。首版不引入手动技能升级或星级解锁核心治疗/控制。
- 五人阵容，3前排2后排。保持3/4/5同阵营加成8%/12%/18%、既有循环克制+25%；文案要与实际作用属性一致，不能笼统承诺全属性。
- 星级基础属性倍率 `1+0.12×星数`；计算时装备和被动遵循统一属性链，不重复加成，生命被动必须影响maxHp。

### 4.2 升星配方

取消兵魂/自动吃其他英雄卡；仅扣本人同名卡和铜钱。

| 星级提升 | 同名卡 | 铜钱 |
| --- | ---: | ---: |
| 0→1 | 1 | 2,000 |
| 1→2 | 1 | 8,000 |
| 2→3 | 2 | 25,000 |
| 3→4 | 2 | 70,000 |
| 4→5 | 3 | 160,000 |

N/R/SR/SSR最高2/3/4/5星。任何星级等级上限均为玩家上限200。5星累计需要9张额外同名卡，属于长期收集，不是首章通关条件。

升星弹窗显示当前→目标星数、实际属性前后对比、材料持有/需要、铜钱持有/需要。校验和扣除一次性完成，保存成功后显示成功；余额不足/取消/连点不扣错。满星按钮显示“已满星”。

### 4.3 多余卡与自选

- 同名卡兑换通用碎片默认每张N/R/SR/SSR=1/3/15/60，沿用已有碎片资源，不加新币。
- SR/SSR默认保护；批量只列已满星、未锁定N/R多余卡。非满星/高稀卡要单独主动选择并解锁保护、确认明细。只兑换卡数，不删除本体/星级/装备/上阵关系。
- 自选SR150碎片、SSR500碎片；保留现有每天满活跃30碎片来源。仅靠这条来源，SSR需17个达标日，不能写“第17天必送”。兑换所得卡再次转碎片应亏损，验证无循环套利。
- 购买先获得持久化券 `vouchers.sr / vouchers.ssr`；打开/关闭选择窗口不消耗。确认选择时券−1与英雄获得在同一保存中完成。重复确认不重复扣/发；断线重启仍有未使用券。
- 自选范围对应稀有度完整常驻池，可选未拥有或已拥有者。未拥有→解锁且共享玩家等级；已有→同名卡+1。
- 目标标记只显示收集/兑换进度，明确“不影响招募概率”。

### 4.4 新手可玩保障

既有刘备/关羽/张飞/廖化保留，建号补孟达（`mengda`，N射手）并自动上阵为第五人：前排张飞/关羽/廖化，后排刘备/孟达。旧档无孟达者补首次解锁，已有者不补卡；旧阵容不覆盖，仅给空第五位补位，不替换用户有效位置。

首关胜利给一次“刘备/关羽/张飞同名卡三选一”的新手教学权益，持久化后自主领取，不强制消耗；本体本就拥有，因此选定同名卡+1。第一章通关增加一张常驻SR自选券，既有章末元宝/招募令照旧。存档需独立一次性标记；已达条件旧号补未发权益一次。明确这是新手/章节奖励，不能做成抽卡保底。

先对约20名代表英雄做职责与配合验收，全部120将仍要无undefined/NaN、技能可释放/文案机制一致；禁止其余英雄只剩占位技能。推荐代表覆盖初始5人、单体/群体输出、治疗/护盾、控制/驱散与四阵营，选名单时以实际技能为准。

## 5. 结算契约：经验和奖励只能发一次

推荐入口：

```js
beginBattle({ mode, stageOrFloor, formation })
// -> { battleId, seed, snapshot, rewardSpec }
settleBattle({ battleId, outcome })
// -> { ok, alreadySettled, levelBefore, levelAfter,
//      expBefore, expAfter, gainedXP, reward, unlockedRewards }
```

`beginBattle` 校验可挑战性，生成存档内单调递增seq组成的ID，冻结参考等级、首通资格、阵容、属性、奖励规则和种子；演武在这里预留一次次数。`outcome` 只能由该局引擎结果传入，UI不能自行构造胜利奖励。

同一存档只允许一局活动战斗。保存 `battle.nextSeq / pending / lastSettled`，其中lastSettled含ID和结算摘要。结算采用“校验ID与状态→在克隆状态上计算等级、资源、首通、任务、新手权益→整档写入成功→替换内存态→展示”的单一事务；存储失败不显示已领取，允许安全重试。不是依次改几个全局变量再各存一次。

- 重复结算最近一局返回原摘要，不再发奖；旧局回调与当前pending不匹配则拒绝，不污染新局。
- 重启遇到pending未结算：首版按中断/撤退收尾，不发经验、不推关；已预留演武次数不返，界面提前说明。不要擅自“补胜利”。已settled的返回原摘要，不能再发首通。
- “跳过”只让同一引擎用相同固定逻辑步长跑到结束，仍同一ID。正常播放/倍速/跳过应有同种子同结果。
- 若保留广告复活：仅战役/塔可一次，演武/练兵不提供；败局先进入待复活状态，玩家退出才最终失败结算。复活沿用ID与原奖励快照，恢复己方至30%maxHp，敌方血量/状态保留；己方清除导致无法继续的死亡/控制状态；延长战斗时限默认15逻辑秒一次，配置集中。广告未完成不复活；禁止重建满血敌人。可用一次免费重战作为普通替代，但那是新ID。此项若实现未通过验收，应先关闭复活入口而非保留错误行为。
- 结算页按钮只导航。关闭页面、点击继续或看奖励广告都不能重发基础经验。广告追加物品奖励另设该battleId下的单次领取标记。
- 防重适用于本地正常流程/异常回调，不宣称本地小游戏具备服务端防作弊能力。

## 6. 存档与旧档迁移

字段结构示意（版本号采用**实施时现有版本+1**，不要和其他地图/剧情执行者抢占v4）：

```js
{
  version: NEXT_SAVE_VERSION,
  player: { level: 1, exp: 0 },
  roster: { guanyu: { star: 0, cards: 0, equip: [null,null,null,null], lockedCards: true } },
  vouchers: { sr: 0, ssr: 0 },
  heroProgress: { starterMengdaGranted: true, firstWinChoiceGranted: false,
    firstWinChoicePending: false, chapterOneVoucherGranted: false },
  battle: { nextSeq: 1, pending: null, lastSettled: null },
  migrations: { playerLevelV2: { applied: true, anchorId: null, compensationGold: 0 } }
}
```

roster没有个人有效等级；可以在迁移备份中保留旧lv追溯。已选新手SSR权益与普通SSR券区分，不能误让三选一变成16选一。已有未知字段应保留，不能因本方案删除另一任务的剧情/地图状态。

迁移步骤：

1. 读取旧档并备份原始快照到独立迁移备份key，不覆盖主key直到成功；不要重置损坏或更新版本档为新号，应保留并返回可诊断错误。
2. 先按旧规则结算一次旧离线时长和上限，保存到待迁移的内存副本；原档/真机测试数据不用于开发测试。保留招募令小数余量，不能floor后丢掉积累。
3. 对有效已拥有英雄取**最高旧真实lv**作为玩家等级，限制1–200；不用共鸣显示等级。多名并列时按heroId稳定排序选anchor。新等级内经验0。
4. anchor的升级投入已转化为全队等级，不再退款。其余当前英雄按旧升级成本公式逐级重建真实lv的铜钱/兵书投入：铜钱100%退回、兵书按1:1折铜钱。不是按新公式或当前有效等级估价。
5. 库存`res.exp`与挂机桶`idle.exp`（包含步骤2的离线结算）同样1:1折铜钱，然后移除活跃兵书字段。保留原铜钱和其他资源，不重复领取原挂机桶gold。
6. 原星级、同名卡、装备库存/归属、阵容、抽卡总数、关卡、塔、演武、任务领取、剧情阅读状态原样保留；清理无效个人升级引用。补第4.4节满足条件的新手权益，标记一次。
7. 写入完整新档、迁移版本和补偿摘要，一次成功后切内存；重载不得再退。提供一次可关闭的摘要“全体共享Lv.X；已折算铜钱Y”，不阻断正常游戏。

只补偿当前存档可重建投入。以前已经重置/遣散、档里无账本的投入无法还原，不承诺历史全部返还。迁移测试必须覆盖v1/v2/v3链式升级以及实施时最新版本，不能假定其他harness未改存档。

## 7. UI规格与占位图

### 7.1 通用规范

以375×812逻辑尺寸为参考，必须同时适配375×667与实际窄屏。横向边距16，间距8/12/16，主要点击目标至少44×44；正文14–16，辅助文字12–13。尊重平台安全区/胶囊区，内容实际高度=`可用高度−顶栏−底栏−安全区`，不能把812的坐标直接写死。

沿用墨黑/鎏金/朱砂主题：背景近`#111820`、面板`#202A34`、主操作金`#E8C47D`、正文近白、次级文字`#AAB5BE`。稀有度N灰/R蓝/SR紫/SSR金，**颜色旁必须有N/R/SR/SSR文字**。阵营文字固定一处，不只靠颜色区分。

一级页面沿用项目既有底部导航；原型只画主城/武将/编队/招募方便演示，**不要求照原型删掉现有王庭等入口**。详情为二级返回页；模态框最高层遮挡并阻止底栏/背景点击。加载/空列表/资源不足/满星/满级/锁定状态均需明确反馈。

### 7.2 五个关键页面

| 页面 | 固定信息 | 主操作 | 次操作与状态 |
| --- | --- | --- | --- |
| 主城 | 玩家等级、经验条、铜钱/元宝；下一关；当前5人 | 出征 | 练兵、重战上一关、调整编队；满级替代经验条说明 |
| 武将列表 | 已拥有数/120、全体共享Lv.X | 点卡进详情 | 第一行阵营，第二行稀有度/排序；自选券与多余卡入口；有清空筛选空态 |
| 武将详情 | 头像、全名、稀有度/阵营/职业/职责、星级、共享等级、实际属性、技能、装备、同名卡 | 升星预览 | 上阵/更换、卡片保护、定向获取；没有个人升级按钮 |
| 编队 | 前3后2、全体共享等级、阵营加成及实际战力 | 选位置→选人→保存 | 已上阵英雄交换位置；未拥有不可选；返回未保存需保留草稿或明确确认放弃 |
| 战后结算 | 胜负、玩家经验、Lv前后/剩余经验、全体同步提示、实际奖励 | 下一关/再战 | 返回主城/地图、调整编队；失败给练兵；满级显示正常物品奖励 |

卡片建议三列，列宽约107px（375−32边距−20间隔）；头像区约94px，姓名独占一行在头像下，随后职业/等级和星数。同名卡、已上阵角标不盖全名；不能恢复原“姓名压头像、同一排所有筛选溢出”的布局。长名最多一行缩字号到14仍放不下再省略，详情显示全名。

默认排序：已上阵优先→稀有度→星级→固定英雄顺序；“可升星优先”必须同时检查卡数和铜钱，“同名卡数量”用于整理。保留筛选状态和滚动位置；从详情返回不要跳回列表首屏。

### 7.3 占位图可直接实现

第一版制作5张职业模板：盾甲（坦克）、刀/戟（战士）、弓（射手）、羽扇（军师）、杖/医箱（辅助）。阵营以底色+文字区分；英雄姓名独立放图下；可用人物轮廓/头盔形状的小变化，不靠现成游戏立绘。

运行时推荐程序化Canvas绘制并缓存为离屏画布/位图，经统一`heroFace`适配现有渲染器，避免微信/抖音对SVG图片支持差异。若用导出的PNG，放`src/assets/placeholders/`，现有build.js递归复制；不要只放仓库根assets而忘记双平台打包。HTML原型内联SVG只是设计参考，无需在运行时加载SVG。

- heroId→portraitKey映射集中维护；渲染接口如`drawHeroPortrait(ctx, heroId, x,y,w,h)`，今后换正式图片不改页面布局。
- 单图1:1或约1:1.1，输出资源可用256px；绘制按设备像素比正确缩放，缓存按职业/阵营/尺寸复用，不每帧生成120张。
- 异常/加载失败有默认轮廓，卡片仍可识别和点击。不因为缺图片挡住游戏。
- 如替换真实图，姓名/稀有度/星级仍是UI元素，不烘焙在图片里。
- 只用轻量选中描边、按钮反馈、升级提示；首版不做满屏粒子或稀有度常驻闪烁。

### 7.4 UI前置修复

统一在`src/ui.js`与`src/app.js`修正：滚动绘制变换与点击坐标一致；点击/拖动阈值建议8逻辑像素；滚动区域裁剪外不能响应；模态蒙层遮断底栏与背景；safe-area后再算布局；小屏长列表/弹窗可滚动且底部确认按钮可到达。所有场景继续使用IMGUI公共控件，不私自接管触摸。

## 8. 实施批次、接口与文件归属

实施者先读AGENTS与session_context，检查git status和最新源码；与其他执行者核对热点owner、版本号及地图/剧情状态。下面是顺序，不是同时改同一文件的授权。

| 批次 | 工作 | 主要文件 | 退出标准 |
| --- | --- | --- | --- |
| A 规则和存档 | config参数、唯一等级、经验纯函数、迁移、兵书清理、英雄归属、升星/券事务 | utils/config.js、store.js、items.js；可新增utils/player.js分离纯计算 | 单元/迁移/资源守恒通过，存量调用无断链 |
| B 战斗闭环 | begin/settle、固定步长、跳过一致、塔修复、练兵、关卡倍率、maxHp被动 | utils/battle.js、stages.js、src/screens/battle.js | 新号可战斗升级；重复结算无收益；普通与跳过一致 |
| C UI组件 | 布局、点击坐标/模态、安全区、职业头像缓存 | src/ui.js、theme.js、app.js及头像模块 | 小屏触摸/遮罩/滚动先通过 |
| D 页面接线 | 主城/武将/详情/编队/招募/兑换/结算，旧入口清理 | src/screens下对应文件、scenes.js按需 | 所有交互调用内核接口，实际状态刷新正确 |

强耦合A/B和热点由负责人串行收口。数据纯函数测试与UI组件可在接口冻结后交给不同owner并行。`store.js/config.js/app.js/ui.js/session_context.md`同一时刻一个owner；子执行者不自行合并另一人的未验证改动。

建议公开API：`playerInfo()`、`effectiveLevel(id)`、`calcHero(id)`、`ascendPreview(id)`、`ascendHero(id)`、`convertCards(selection)`、`buyChoiceVoucher(rarity)`、`useChoiceVoucher(rarity,id)`、`beginBattle()`、`settleBattle()`。命名可适配现有结构，语义必须统一。场景不得自行减卡、加XP或推关。

兼容性：`utils`不能依赖`src`；wx/tt只在platform适配层；无第三方运行时。legacy不移植UI，但共享内核的旧调用不得导致档损坏或偷偷产生个人等级；保留必要兼容包装并明确停用个人升级。
