# 《剑与远征》PVE 体验总总结与《挂机定三国》打磨方向

日期：2026-09-27
对象：当前 iPhone 上的原版《剑与远征》，客户端版本号未核实
依据：三轮 iPhone 镜像实际操作、客户端说明、已保存的体验记录
用途：产品决策、玩法与 UI 借鉴、其他 harness 拆分实施任务

> 本文汇总“截至目前已经体验的内容”，不是全游戏通关报告。产品建议与实测事实分开表达；未覆盖的玩法和状态列在文末。暂不讨论美术，礼包、充值、PVP 不在研究范围。

## 1. 最重要的结论

**继续做低负担的挂机游戏，这个方向可以保留。优先打磨“容易开始、持续推进、收获明确、变强可见、回来有下一步”这条循环。**

三轮体验最有价值的发现，是原作把多个简单动作接得很紧：主线在自动打，玩家可以去看英雄、培养、领收益；回到主线又能看到推进结果。抽到英雄、强化装备、完成任务，各自有明确结果，再把玩家带回下一次挑战。

对《挂机定三国》的产品判断是：玩家可以不研究复杂攻略，但仍需要知道自己为什么变强、接下来期待什么。减少计算和重复操作，同时保留少量直观选择，例如是否采用推荐阵容、是否尝试可选的爬塔目标。

现阶段最值得投入的是以下四件事：

1. 主线自动出征完整顺畅，开始、持续、停止、返回都有交代。
2. 收到英雄或养成资源后，玩家能看见它对队伍的真实作用。
3. 卡关后有当前能做的下一步；暂时不能成长时，也能知道等待会得到什么。
4. 领取、培养、召唤、返回等基础交互可靠，减少误触和无意义点击。

这些是基于本次操作的设计判断，不是已经用留存数据证明的结论。增加系统数量、复制原作全部养成线，都不应成为首发目标。

## 2. 这次实际体验到了什么

研究使用已有进度的账号，无法代替新手体验。三轮主线从待挑战22-10推进至待挑战22-47；最后停在正常战役首页，自动推关已结束。

| 模块 | 实际操作与结果 | 仍有的边界 |
| --- | --- | --- |
| 主线与自动推关 | 单场胜利、站位拖动、自动必杀、倍速、暂停；连续推图；切英雄和其他页面继续；主动停止与切玩法停止汇总 | 未测自然失败后的完整自动恢复、跨章演出 |
| 召唤 | 普通池十连、逐张/快速揭示、新英雄与技能查看、附奖；查看概率和心愿单 | 其他卡池、长期概率、隐藏保底未测；发生过超授权误触，见第8节 |
| 挂机 | 普通领取、领取后空态、跨页累计、短后台回流；一次50钻快速挂机 | 长离线封顶、断网、杀进程未测 |
| 英雄与培养 | 列表/筛选/详情；装备实际强化；共鸣加槽；四组批量进化；职业树和秘典各升一级 | 主力品质突破、共鸣移除冷却、高阶养成未完成 |
| 王座之塔 | 251层失败、查看战报、交换站位后胜利 | 单次样本，不证明换位必胜；阵营塔未实战 |
| 迷宫 | 多场战斗、借将、选路、遗物、温泉、阵亡保留、两次道具恢复、重试 | 卡在第一层后段，未完成跨层与最终结算 |
| 时光之巅 | 副本目录/完成度、继续已有浩劫之地、补阵战胜一处敌营、地图宝箱与遗物、日志、返回保留探索 | 机关、最终奖励与完整通关未测 |
| 悬赏与任务 | 批量领取/派遣、条件不足；日常积分和宝箱批量领取；主线里程碑单项领取 | 团队悬赏、周常等未完整验证 |
| 其他系统 | 背包道具预览、奇境漫游详情、主神试炼锁定条件 | 只查看的页面不能当成已经深测 |

## 3. 核心循环为什么值得借鉴

以下每项先列实测，再给产品解释。解释用于提出设计假设，不用来宣称原作的实际商业或留存效果。

### 3.1 主线让成长有一个容易理解的方向

**实测：**战役首页同时展示当前关、路线、战斗队伍、挂机宝箱和挑战按钮。章节页能查看未抵达章节的产出与奖励预告；胜利结算同时展示奖励和任务进度。

**产品解释：**玩家不需要自己寻找目标。当前关回答“我到哪了”，下一节点回答“再推进一点能拿什么”，挂机宝箱回答“停下来也在积累什么”。地图的价值首先在于表达进度和目标。

**本项目适配：**继续打磨已有战役首页，突出当前关、下一项真实奖励、当前队伍和自动出征。常用操作应能直接到达，不让次要入口挤占主动作。

### 3.2 自动推进释放注意力，但需要持续反馈

**实测：**原作自动推关期间可进入英雄、领地、图书馆、悬赏；底栏持续显示当前关。开启塔战前才提示将中止主线自动。再次返回主线，会给停止原因、22-47进度和累计奖励。

**产品解释：**玩家可以在同一次游玩里同时感受到推图进展和成长操作，减少“只能盯着战斗等结束”的空档。停止后有摘要，也让离开战斗页的时间有结果可看。

**本项目适配：**跨页面自动会话值得单独实施。它涉及战斗生命周期和奖励结算，不能只开放底栏点击。应用内切页继续与应用进入系统后台必须分别处理；首版不因此增加离线自动通关。

### 3.3 挂机把离开游戏变成可预期的积累

**实测：**普通宝箱展示时间、速率、掉落与领取；领取后重新计时。短后台返回仍继续积累。快速挂机一次支付50钻，获得120分钟收益，随后剩余次数4→3、下次价格80。

**产品解释：**挂机的满足感来自“这段时间换来了多少东西，以及这些东西现在能做什么”。仅让余额变大，而不连接成长用途，会削弱回流的意义。

**本项目适配：**展示真实累计收益、上限、成长用途，以及实际存在的下一档产出变化。固定产出不要伪装成每关都上涨。保留一键收获，并让领取结果能够直达可用成长。

### 3.4 召唤的价值要延续到结果页之后

**实测：**十连包含逐张揭示、品质反馈、新英雄展示、技能查看和附奖。新英雄有单独的认识过程，结束后可以返回收藏与培养系统。

**产品解释：**揭示提供期待，新角色提供新鲜感，能否进入队伍则决定这次获得是否有用。重复卡也需要明确的结果解释，否则玩家只记住“又重复了”。

**本项目适配：**结果至少区分新武将、重复升星、满星溢出。显示实际变化，提供查看职责、推荐编队和完成入口。沿用项目现有概率与价格，不因为原作有多个池就新增多个池。

### 3.5 养成需要“花了什么、改变了什么”的证据

**实测：**一次装备强化先预览材料、802K金币成本、星级与属性变化，确认后更新；弗克斯显示战力128K→129K、攻击17320→17500。职业分支与秘典也展示受益范围、材料和下一等级效果。

**产品解释：**成长反馈的可信度比按钮数量更重要。玩家应该能确认资源确实换来了可理解的变化。

**本项目适配：**共享军械展示受影响的全队属性；自动升星展示原星级到新星级；统一等级明确解释来源。无需恢复原作逐个英雄、逐件装备的管理负担。

### 3.6 少量阵容选择可以保留参与感

**实测：**塔251层培养后仍失败；交换卢修斯和雪米拉前后位置，显示战力仍1497K，再战胜利。迷宫也出现我方显示战力远高于敌方仍失败的情况。

**产品解释：**单一战力无法解释所有战斗结果。阵容职责和站位可以成为可选深度，但不能要求挂机玩家每次失败都研究长战报。

**本项目适配：**提供基于已有武将的推荐编队和简单职责说明，允许手动调整。失败引导优先指向真实可用行动；不要显示“战力更高必胜”，也不要根据单次战报自动断言唯一失败原因。

## 4. 各玩法在产品里承担什么作用

| 玩法/系统 | 本次观察到的作用 | 建议取舍 |
| --- | --- | --- |
| 主线推图 | 最稳定的进度与成长检验目标 | 首发核心，先做顺 |
| 挂机与快速收益 | 时间积累、回流领取、补充养成资源 | 首发核心，先保证结算和用途明确 |
| 招募与武将收藏 | 新角色、队伍变化、重复卡处理 | 首发核心，结果直接连接成长/编队 |
| 统一培养与共享军械 | 本项目已有的减负方式 | 保留，强化反馈与可理解性 |
| 普通塔 | 复用战斗，提供另一条进度和奖励 | 后续打磨已有塔，不急着扩阵营塔 |
| 悬赏 | 定时派遣和批量领取 | 先借鉴批量交互；不必立即新增系统 |
| 迷宫 | 选路、借将、遗物、持续血量带来局内变化 | 核心循环稳定后再立项，保持自愿参与 |
| 时光探索 | 收集目标、路线、剧情线索和持续探索存档 | 内容与交互成本较高，延后 |
| 共鸣、进阶、职业树、秘典 | 共享培养、收藏带来额外收益、多条成长目标 | 学说明与反馈，不整套复制成长树 |
| 日常与主线任务 | 把已有行为转成奖励和下一目标 | 优先打磨已有任务，避免强制玩家做全部模式 |

迷宫和探索确实提供了更多变化，但本次操作中也明显需要更多点击、阅读和判断。对于“用户不用多考虑”的定位，它们适合补充主线，而不是每天的必修流程。

## 5. UI 与交互总结

### 5.1 页面信息应该围绕玩家当前的问题组织

| 页面 | 玩家首先想知道 | 应优先展示 | 主动作 |
| --- | --- | --- | --- |
| 战役首页 | 我现在能推进到哪 | 当前关、下一目标、队伍、挂机状态 | 自动出征 |
| 备战 | 我的队伍是否准备好 | 敌我、职责、站位、可用英雄 | 开始战斗 |
| 战斗结束 | 这次得到什么，接着做什么 | 结果、奖励、推进、相关目标变化 | 继续或成长 |
| 挂机领取 | 离开期间积累了什么 | 时间、上限、真实收益 | 领取 |
| 召唤结果 | 获得了谁，对我有什么用 | 新将/升星/溢出、职责和变化 | 完成/查看/编队 |
| 成长页面 | 花多少、提升多少 | 当前→结果、成本、受益对象 | 明确培养 |
| 任务页面 | 哪些能领，下一步是什么 | 可领取项、里程碑、准确前往 | 批量领取/前往 |
| 副玩法入口 | 是否可玩，还差什么 | 进度、奖励、解锁条件 | 继续/挑战 |

### 5.2 最值得借鉴的细节

- **前后对比：**培养前就能看成本与变化，成功后在原位置更新，不让玩家自己记旧数值。
- **状态明确：**已通过、当前、下一关、未解锁、已完成、可领取、材料不足分别表达。
- **条件可解释：**共鸣品质限级、进阶缺材料、试炼前置要求，都应说明原因。
- **批量处理：**悬赏可一键匹配和派遣；日常实测点一行就领取所有已完成项，点一个可领宝箱会收多个档位。
- **主线里程碑连续：**领取22-12后，同一行出现22-16，目标不会因为领奖消失而让玩家失去方向。
- **冲突延后确认：**浏览其他玩法目录不打断主线，到实际开战前才处理会话冲突。
- **返回有上下文：**自动推图结束后回到主线仍有摘要；探索退出后可以继续已有进度。

### 5.3 不建议照搬的交互

- 揭示完成后，同一位置迅速变为再次付费按钮。本次确实发生额外召唤误触。
- 点挂机面板空白处也领取。操作意图不够明确，本项目应采用明确领取按钮。
- 按钮写“领取”，实际批量处理，却没有提前表达范围。本项目可以直接写“领取全部”。
- 失败页列多个泛泛成长方向，却不说明当前哪个能做。应按真实资源与条件突出一个可执行入口。
- 成长入口只跳到系统总列表，仍要重新寻找目标。能直达对应对象时应保留上下文。
- 大量系统入口和红点同时竞争注意力。首发应突出主线、成长、收获，次要入口按阶段出现。

这些取舍关注操作效果，与是否有高质量画面无关。

## 6. 《挂机定三国》的建议实施顺序

下表为建议范围；不代表本轮已经改代码，也不自动批准数值、存档或战斗规则改版。实施者必须先核对最新源码与交接，复用已存在功能。

| 顺序 | 交付内容 | 玩家能感知到的结果 | 验收重点 |
| --- | --- | --- | --- |
| 1 | 输入与资产结算可靠性 | 连点、跳过、返回、切后台不多扣、不漏奖 | 消费单次提交、结算去重、动画与资产分离、失败可恢复 |
| 2 | 主线目标与挂机反馈 | 进首页就知道当前目标；领奖后知道得到什么 | 真实进度/奖励/速率、领取前后状态、下一目标明确 |
| 3 | 成长和召唤结果闭环 | 新将、升星、军械培养能解释队伍变化 | 受益范围准确、前后对比、直达编队或出征 |
| 4 | 跨页自动出征 | 队伍继续打，玩家能处理成长和收获 | 唯一战斗会话、切页不重复结算、冲突提示、停止摘要 |
| 5 | 卡关后的可执行路径 | 失败后不用到处找系统；暂时无提升也知道等待目标 | 推荐基于已有资产，不强制付费/广告/读攻略 |
| 6 | 首日、次日回流与真机收口 | 新玩家能独立玩懂，回来可以顺利再推进 | 新号流程、长离线、生命周期、旧档、小屏和弱网 |
| 7 | 已有塔与少量可选内容 | 主线之外有选择，但不增加每日负担 | 不成为主线强制前置，奖励有用途，入口清楚 |

第1—3项先形成可靠的基础体验；第4项按独立架构改造交付；第5—6项决定是否接近可发布的产品品质。迷宫和时光类玩法在此之后再判断是否需要。

### 给执行者的范围约束

- 保留统一等级、共享军械、重复卡自动升星，除非另有明确产品决定。
- 原作2前3后与项目现有站位是规则差异，不能通过UI调整偷偷改内核。
- 沿用本项目现有抽卡概率、价格、挂机上限与资源类型；参考账号数值不成为项目配置。
- 不引入新的成长货币、多个召唤池或大量日常，仅为填满页面。
- 武将、技能、文案、场景与素材保持原创三国内容。
- 每批说明玩家行为如何变化、复用了什么、验证了什么，再提交；不要一次把所有参考功能塞进项目。

更细的输入保护、主线、跨页会话、挂机、召唤与成长规格见[v2执行规格](afk-core-ui-interaction-spec-v2.md)。该文档的源码差距是当时核对结果，实施前需要重新确认。

## 7. 如何判断产品真的变好了

先用能观察的玩家行为判断，不用“系统更多了”作为成功标准。以下为本项目建议验收方式，并非原作数据或平台官方审核标准。

### 三条必须走通的体验路径

1. **新玩家首次进入：**看到当前目标 → 开始出征 → 收到明确奖励 → 获得一次可理解成长 → 再次出征。记录每处犹豫、误触和必须询问解释的地方。
2. **首次卡关：**知道已停止 → 获得当前可用的成长/推荐编队提示 → 看见真实变化 → 返回重试；没有可用成长时，准确显示缺口和挂机获得方式，不能承诺等待后必胜。
3. **回流：**进入游戏 → 看懂离线收益 → 一键领取 → 处理少量成长 → 继续推图。核对时间、资源、上限与存档一致性。

### 应记录的观察数据

| 观察项 | 用来判断什么 |
| --- | --- |
| 首次开始出征前的操作数、用时、提问 | 主动作是否足够清楚 |
| 单次领取后，玩家能否说出得到什么和用途 | 收获反馈是否可理解 |
| 抽到新将或重复卡后，是否理解结果 | 召唤是否真正连接成长 |
| 第一次卡关的位置、持续时间、处理动作 | 难度与成长供给是否匹配 |
| 一次回流需要多少重复点击 | 减负是否落实到交互 |
| 误触、重复扣费/发奖、状态丢失次数 | 基础可靠性是否达到发布要求 |
| 陌生玩家是否自发再开一轮 | 核心循环是否产生继续玩的意愿 |

先记录基线，再比较改动前后，不凭本次参考号通关速度设定所有新手数值。邀请少量未参与开发的玩家实际操作，比开发者自己反复熟练点击更容易暴露问题。

微信首发还需要单独完成平台适配、真实广告入口处理、存档/生命周期及提审准备；抖音共享代码也应分别验证。本次参考游戏体验不能替代这些工作。
