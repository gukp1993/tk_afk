# UI 美术首批接入

日期：2026-10-03；执行者：Codex；状态：已实施待验收；仅微信小游戏。

用户授权：直接生成并实现页面按钮、边框和文字美术。沿用当前墨绿/朱红/纸黄/描金风格，未改变玩法、数值和存档。

## 资源与实现

内置 imagegen 分别生成五张透明 PNG；完整源图与提示词保存于 `output/art/ui-v1/`，运行资源保存于 `assets/resources/art/ui/`。运行图裁透明空边、缩小并量化，合计 58,080 字节。

- `ui_button_red`：朱红描金按钮（384×80）。
- `ui_panel_jade`：墨绿描金面板（384×192）。
- `ui_panel_paper`：纸黄描金面板/弹窗（384×192）。
- `ui_frame`：中空透明描金边框（384×80），筛选/分页选中色透出。
- `ui_logo`：挂机定三国书法题字（550×146）。

`ArtService` 统一预载 resources/art；背景图使用 Cocos 九宫格 Sprite，固定原控件尺寸。通用按钮与宽面板、导航背景、纸色弹窗自动换肤，主城标题替换为书法图。大字号标题增加细描边。动态文字保留 Label，保证等级、奖励与技能实时更新。

圆章、英雄占位、品质卡、半透明遮罩、进度条保留专用结构；带颜色语义的筛选 chips 使用中空边框保留原色；不将它们误换为矩形皮肤。原有语义边框在皮肤上层绘制。

## 验证口径

检查加载完成后的主城/主线/玩法/英雄/背包/召唤/编队与各功能页；确认底板不越出控件、标题与资源栏互不覆盖、未获得英雄和筛选选中态正确。无资源时继续原 Graphics 回退。源码检查、smoke、200 种子仿真和 Creator 微信包构建结果在交接补记。

独立代码评审发现英雄占位与筛选状态覆盖问题，已以显式跳过皮肤、保留选择控件及顶层语义边框修正。首轮实拍发现图片原尺寸覆盖布局，已改为赋图片后设置 UITransform 尺寸；首轮截图不是交付证据。

真机/微信开发者工具人工验收尚未进行。当前没有把所有静态文字逐字转成图片，也没有新增货币/导航图标；此批是可复用 UI 底板与主城题字接入。
