## 先看原型

打开 [index.html](index.html)，可直接在浏览器以本地文件打开，不依赖安装包。也可以从仓库根运行：

```bash
python3 -m http.server 8771 --bind 127.0.0.1 --directory docs
```

然后访问 `http://127.0.0.1:8771/hero-ui-handoff-v1/`。不要只服务本目录，否则上一轮参考样稿的相对链接不可访问。

原型可操作：阵营筛选、战力/品质/星级排序、列表滚动、点击关羽进入详情、技能正文弹窗、返回列表、素材册的透明底色切换。全军军械/调整编队/其他导航仅说明正式跳转契约。数字与九名角色是明确标识的模拟展示，不读写玩家存档。

本次关羽使用完整透明立绘；其他武将用姓名占位。完整多人物氛围看[原列表高保真样稿](../prototypes/heroes-v1/hero-roster-v1.png)，详情风格看[原关羽样稿](../prototypes/heroes-v1/hero-detail-guanyu-v1.png)。交互原型是检查组件与路径的工具，不是这些静态原画的逐像素复刻。

## 交付边界和下一阶段

本轮完成设计与开发交接，尚未将新素材接入Cocos运行页面。当前根工程既有页面及其他未提交改动保持原样；现有规则仍为主公统一等级、同名卡自动升星、全军共享军械、每将两个技能。先实现关羽贯通列表和详情，再批量替换其他人物。

“抠图”交付为透明图集+单项坐标，而非33个单独PNG；立绘/背景为独立文件。原图被UI遮挡的地方做了AI补绘，无字控件进行了清理或重建。卡框、按钮尚未验证九宫格inset，默认按SIMPLE显示。提示词配合批准的参考图能约束画风，不能承诺只靠文本绝对一致。

浏览器原型为示例交互，并未实现生产规格中的全量120将、真实持有数、星级空槽、上阵角旗、首胜/多余卡等条件入口、虚拟列表和自动战斗刷新；这些均在产品/开发文档列为正式接入要求。原型字号随浏览器显示适配，正式尺寸以产品稿为准。

## 验证记录

- PNG读取、尺寸、SHA256、真实alpha、35个矩形范围/互不重叠、4个品质框中心近透明（alpha≤8）检查通过。
