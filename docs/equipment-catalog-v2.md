# 军械图鉴 v2：共享解锁与部位养成（设计草案）

日期：2026-09-26。用户要求：设计装备图鉴，减少五名英雄各养一套装备的负担；图鉴解锁的装备所有英雄可同时使用，升星培养共享部位。本轮交付设计与占位交互演示，**未实施游戏功能**。

设计假设：采用一个军械页面管理全队一套六槽配装。全队一套/每将独立配装的选择尚未收到明确答复；六槽、30件、成本、解锁关卡与下列效果均为建议，不是已确认产品决定或经过验证的平衡结论。若用户选择个人配装，只替换“选择哪件装备”的归属，图鉴解锁与部位星级仍共享。

## 1. 玩家能理解的规则

**收集军械图鉴，培养六个部位，一次操作让所有英雄受益。**

- 装备首次获得：永久解锁图鉴条目；不会生成一件需要分配的背包物品。
- 每个部位选择一个已解锁条目，全队所有英雄按同一套军械配置计算；英雄数量不影响消耗。
- 部位星级属于账号；换同槽装备、换英雄都保留星级。英雄仍保留各自星级、技能和基础属性。
- 获得重复装备：自动折成精铁，展示折算明细，不存同名碎片或装备副本。
- 未选中的图鉴没有战斗加成；收集进度不叠攻击，不加图鉴星级或收藏套装。
- 不做个人装备归属、抢装、卸装、背包容量、单件强化、分解/转移培养、随机副词条及阵营匹配。

例子：兵刃位3星，当前选择精钢长刀；新解锁破阵长锋后，点击启用，兵刃仍是3星，全队下一场战斗使用新装备；张飞和关羽无需分别再穿一次。

## 2. 本草案与其他规格的关系

本方案若确认采用，将取代 `equipment-system-plan-v1.md` 的个人四槽、五套20件、阵营匹配、单件强化/返还、背包回收及一键分装等冲突条款。无需先把将被废弃的单件系统全部补齐，再做图鉴。

英雄v2的统一玩家等级与本方案兼容，新英雄同时继承账号等级和部位星级，英雄自身星级仍独立。英雄v2文档中保留旧个人装备的过渡条款需要实施时同步修订。本轮不改其文档、代码或其他会话正在实施的内核。

英雄v2取消个人等级升级消耗铜钱，故本方案的铜钱预算应与英雄升星、商店等剩余支出共同核算，不继续沿用“英雄升级争铜钱”的旧假设。英雄招募四档概率与无保底不变；军械解锁不是新增英雄保底。

## 5. 部位升星与计算

部位倍率 `M(s)=1+0.1×s`，s为0…5；一星提升的是该部位装备加成的10%，不是英雄总属性10%。同部位所有品质都能使用5星倍率。

对属性k：`gearPct[k] = Σ(六槽当前条目的基础百分比[k] × M(该槽星数))`。

英雄等级/英雄星级计算后、装备/个人被动/队伍光环计算前的基础属性记作B：`装备后属性[k] = floor(B[k] × (1+gearPct[k]))`。所有军械百分比先相加，最后取整，不将六件属性彼此连乘。固定效果走独立通道，再由对战规格统一与个人被动、光环结算，不重复灌入英雄被动。

例子：破阵长锋攻击+8%，兵刃3星→装备攻击贡献+10.4%。基础攻击1000的武将增加104，基础攻击600的武将增加62（最后统一取整）；并非所有英雄的最终攻击相同。升4星后该件贡献+11.2%，不是全队总攻击再增加10%。

固定效果详细边界：

- 济世青玉：只乘主动heal/hot的施放量一次，之后按目标缺失生命结算实际治疗；不加盾，不加吸血/被动自愈；持续治疗生成时快照，不能每跳重新叠一次。英雄没有治疗技能时不会凭空获得治疗技能。
- 守心玄玉：在等级、装备、个人生命被动、队伍生命加成全部结算后，以各英雄入场最大生命算盾；每个开战单位一次，护盾不自行刷新，战斗内复活不重复触发，下一场重置。
- 锐进兵符：开场怒气=英雄自身开场怒气＋10，再按怒气上限裁切，不吃怒气获取倍率；不因有五名英雄变成每人+50。
- 磐石兵符：普通攻击/技能直接伤害在既有个人减伤后再乘0.97，再进入护盾吸收；不影响治疗、反伤、持续伤害或明确无视减伤的效果。若对战专题调整伤害类型，此处需同步定义，不能界面写所有伤害而引擎只处理一部分。
- 这些是队伍军械对每人的一次贡献；组队只读取一份配置，不把五名英雄的相同军械当五个光环累加。未来多队战斗可共用解锁/星级，但是否需要不同队伍配装属于另行扩展。

开战冻结图鉴选择、星级、英雄与数值。战外升星/换装只影响下一场；中途暂停、倍速、跳过不重触发开场效果。真实引擎尚未实现这些新装备效果，原型只展示规则与属性，不模拟战斗。

## 6. 解锁、重复与确定获得

只新增精铁一种装备材料，复用铜钱。没有装备抽卡入口、图纸碎片、洗练石、额外部位币，也不新增需要每天刷的装备副本。

建议解锁方式：

1. 新手首次进入军械页，直接解锁并启用六件白装，六槽0星。是一次性初始化权益，重进不重领。
2. 第10/30/60关首通分别开启蓝/紫/橙条目的常驻定向解锁，并发该品质一个自选解锁箱作为首次体验。箱子类别在获得时固定，只能选择当时这一品质的条目。
3. 保留普通战役首通掉落的惊喜，但改发完整图鉴条目或精铁；本草案将原65%掉装概率作为首轮占位，不声称合理。掉落池只能使用已开放品质，N始终开放；本品质解锁关先开池再抽，里程碑奖励与随机奖励是两份不同权益。
4. 建议初始池权重：N/R/SR/SSR为50/30/15/5，未开放档置0后重归一化；先选品质，再等概率选该品质六个部位，再在该部位内等概率选条目。装备概率与英雄招募完全独立，UI需展示当前有效概率。随机掉落不是完成图鉴的唯一途径。
5. 挂机固定产精铁，任何已通关进度都能积累；按已有12小时上限计算，剩余小数保留在持久化的 `idle.ironAcc`，领取时只把整数部分转入 `res.iron` 并扣去已领取量。交易余额与消耗均为非负整数；挂机累计允许有限非负小数，不因频繁领取归零。第一轮示例12精铁/小时，日常活跃奖励另给80精铁；不需要每日成功升星才能拿奖励，满星账号也能完成。
6. 所有未解锁且达到开放关卡的条目，都可以在详情页用固定精铁定向解锁。选择结果确定、无失败。卡在30关以后仍能收集已开放的紫装并培养部位，不需要继续推关才有材料。

| 品质 | 定向解锁成本 | 重复完整条目的转化 |
| --- | ---: | ---: |
| N | 新手固定解锁，无重复购买入口 | 精铁10 |
| R | 精铁100 | 精铁25 |
| SR | 精铁300 | 精铁75 |
| SSR | 精铁900 | 精铁225 |

首次条目入账只解锁、不另送重复材料；同一批奖励获得两份同名条目时，一份解锁、一份按表转化。图鉴存在则不允许付费再次定向解锁；重入/重复回调按同一交易只执行一次。

自选箱关闭不消耗；不能选择已有条目，当该品质已全收集时提供明确的“转为精铁”选项，数量等于该品质重复补偿，需要主动点击。箱子不能自动升级品质，也不能先解锁再通过重复回调收补偿。

全图鉴且全槽满星时，精铁余额继续保留，没有过期、强制清零或已承诺的未来用途；到上限显示当前版本已完成，不用无限星级伪装长线。未来扩容另定方案。

## 7. 成长节奏与避免货币压力

升到1/2/3/4/5星分别消耗：

| 目标星数 | 精铁 | 铜钱 |
| --- | ---: | ---: |
| 1 | 60 | 2,000 |
| 2 | 120 | 4,000 |
| 3 | 240 | 8,000 |
| 4 | 480 | 16,000 |
| 5 | 960 | 32,000 |

每槽从0到5星共1,860精铁＋62,000铜钱；六槽共11,160精铁＋372,000铜钱。六件蓝＋六件紫＋十二件橙全部定向解锁共13,200精铁。若全部靠定向、无首通掉落或赠箱折扣，两项目标合计24,360精铁。

在每天实际领取24小时挂机并完成80精铁日常的假设下，日入368，合计约66.2天精铁供给；每天只领一次12小时则日入224，约108.8天。**仅用于暴露预算，不是“66天通关/毕业”承诺**：品质关卡门槛、铜钱竞争、关卡难度及实际登录都会影响进度，随机与固定奖励又会缩短材料需求。第一版原型数值只是演示，实施须重做7/14/30天样本验证。

为减少升星与收集抢材料的挫败，新手先发60精铁与一次升星所需铜钱完成教学；章节箱独立提供新条目，不强迫玩家在首次体验时二选一。不要增加另一种收集货币来绕过预算问题；优先调整材料收入、定向成本和里程碑发放。

不默认把精铁加入已有广告双倍或快速收获；若后续接入需独立定义倍率/次数，并验证免费日常仍能完成基础成长。兵书已在英雄v2退休，不作为装备新材料复活。

## 8. 页面与操作

入口建议：背包页“军械图鉴”卡片，亦可沿用铁匠铺位置改名“军械”。不新增一个底栏，不让玩家同时找到旧铁匠铺与新图鉴两套规则。

**军械主页面**：顶部“全军共用”＋精铁/铜钱；六槽2列×3行，每格显示部位名、当前装备名、部位星级与“升星”；下方“查看图鉴（已解锁x/30）”与当前全军基础属性汇总。不得将全队战力简单写成某装备数值×5。

**图鉴页面**：按六部位分组/筛选，卡片展示名称、品质、锁定/已解锁/全军启用状态。默认显示当前部位的五件，避免一屏挤30件；总收集数始终可见。星星显示在部位标题，条目卡不重复画一排星误导“每件都要养”。

**详情页面**：名称、品质、所属部位、当前部位星级下的实际基础加成、固定效果、当前装备对比、获得方式。已解锁可点“全军启用”；未解锁且达到门槛可点“精铁×X解锁”，未达门槛显示“通关第X关开放定向解锁”。解锁不会默认替换已有装备，避免收到新战利品悄悄改变阵容；解锁成功后可主动启用。

**升星确认**：明确“升级兵刃位，全体英雄受益”，列当前装备的属性变化、成本与剩余余额；材料不足直接显示缺口及来源。成功一次扣款、一次升星并保存；满星不扣费、不再提示红点。

只对“新解锁未查看”和“可领取一次性奖励”显示提示；升星可用以按钮状态表达，不对30件全部闪红点。换装免费、无冷却，在战斗外即时更换。不要做只按品质覆盖全部槽的“一键最优”，同档橙装存在战术取舍。

英雄详情移除可操作的个人装备格，替换为“共享军械加成：攻击x%、生命y%、防御z%”和跳转军械入口；战报需能识别护盾、额外初始怒气和治疗加成来源。新英雄详情首次显示“已享受当前军械，无需重新培养”。

本轮聊天内占位原型用于体验上述动作，含示例账号资源与解锁状态，可操作六部位、详情、解锁、启用、升星；不会访问游戏存档。原型不是实际Canvas页面或战斗验证。

## 9. 最小数据与接口契约

定义层：`catalog[id] = {id, slot, q, name, basePct, effect, source}`，固定表，不按英雄复制。配方/概率/星级曲线集中配置，不写在Canvas页面中。

状态建议：

```js
armory: {
  schema: 1,
  unlocked: { weapon_n: true /* ... */ },
  selected: { weapon: 'weapon_n' /* 其他五槽 */ },
  slotStars: { weapon: 0, armor: 0, helm: 0, boots: 0, jade: 0, seal: 0 },
  seen: {},
  claimedMilestones: {},
  boxes: { r: 0, sr: 0, ssr: 0 }
},
res: { /* 其他资源保留 */ iron: 0 }
```

军械schema不代替主存档版本；主版本按实施时最新值递增。交易去重复用统一战斗/奖励结算机制，不在每个条目创建无限增长日志。边界函数：获得条目（解锁或重复转化）、定向解锁、打开指定品质箱、启用条目、部位升星、获取共享加成快照。

核心约束：合法条目/部位、解锁状态、关卡门槛、非负整数资源、星级边界；完整校验后原子提交。图鉴只存布尔归属不存份数；同名随机奖励连续获得仍必须按每次独立合法奖励正确转化，不能把“重复奖励ID”和“重复装备条目ID”混为一谈。

改动预计落点：新增纯逻辑配置/模块，store接入资源和迁移，英雄属性计算替换旧装备叠加，battle接入固定效果，军械/详情/背包UI替换，原有战役装备掉落改为图鉴奖励。共享源码修改后由build同步平台包，禁止手改生成物。

## 10. 旧档迁移需要单独验收

旧存档是真实个人装备实例；不能直接把装备数组去重后当作无损迁移，也不能将“全队共享”当成复制旧物品五倍补偿。

建议迁移方法：

1. 备份旧快照，以装备唯一ID扫描总装备表（包含穿戴与背包），每个实体只计一次；英雄引用用于查完整性，不再次计资产。
2. 旧四槽按同槽同品质映射到新图鉴的唯一N/R/SR条目，旧SSR默认映射该槽A款。玉佩/兵符给白装。旧阵营不带入新机制；缺阵营也可映射。第一件对应模板解锁，后续同模板物品按新重复表补精铁。迁移默认配装为各旧槽最高已有品质的映射条目（SSR选A款），不存在旧装的槽与新两槽选白装；不把所有旧玩家统一换回白装。
3. 全部旧强化星数按旧配置重建最低必需强化点/铜钱，合计作为迁移可返还额度；首轮试算按旧1强化点→新1精铁、铜钱1:1。历史超额材料或已销毁物品无法精确追回，不能声称完整还原真实投入。旧v1/v2必须先走其合法迁移链。该折算可能使高积累老账号提前毕业，必须在旧档样本验证后确认，不能未经验证上线或暗中截断补偿。
4. 为保留培养观感，可将每个旧部位最高星数作为目标，用同一返还预算支付新部位曲线；明确按兵刃→铠甲→头盔→战靴顺序逐槽逐星支付，预算不够则停在可支付星数（未达到的目标展示差额）。剩余退余额，新增两槽0星。不能既免费继承星数又全额退款；迁移明细列重建额度、继承花费、退还余额。该自动分配顺序也需随迁移样本验收确认。
5. 迁移解锁的高品质可以立即使用，不要求已达新掉落门槛；定向解锁新条目仍按进度。新手赠送/里程碑补领取只执行一次。
6. 旧装备固定加成变成百分比加成，无法未经验证保证所有英雄属性不降。实施前使用早中晚旧档比对，制定可解释的补偿/过渡方案并确认；若无法接受则该迁移不得上线。旧备份只读保留，不保留两套装备同时生效。
7. 主版本/军械迁移标记保证重复加载只兑换一次；未知新版本不重置成新号；非法引用修复记录不能成为复制资源的入口。

迁移映射与补偿只是建议，尚未计算真实存档样本；不能据本段直接清空用户旧装。本轮没有读写任何设备存档。

## 11. 实施与验收

交付顺序：确认共享配装方式 → 固定图鉴/六槽状态/资产事务 → 基础属性与战斗快照 → UI与稳定获取 → 四个战术效果 → 旧档补偿与双平台回归。页面/规则可以分文件并行，store/config/session等热点由主负责人收口。

关键验收：

- 获得一件装备后所有英雄可同时使用；启用只改变该槽，不生成五个物品实例。
- 兵刃3星换另一把兵刃仍3星；换武将不扣资源，也不丢进度。
- 未启用条目不加属性；30件全解锁不比同配装6件解锁多战力。
- 兵刃升星只改变兵刃的基础百分比，固定效果数值不随星数偷偷变大。
- 一人队与五人队每人获得的共享百分比一致；开场盾/怒气不乘队伍人数，不重复触发。
- 首次获得解锁，第二次按表转材料；同批两份、重复回调、跨重启均正确。
- 未解锁不可启用；槽位不匹配、余额不足、未达门槛都零变更。
- 自选箱取消不扣箱；该品质全满可主动折材料且不重复领。
- 铜钱/精铁不足和5星满级不会扣费；挂机小数不因频繁领取损失。
- 320/375宽度下六槽、详情、长说明和升星操作不超屏；弹层不穿透，触控无需悬停。
- 抽到新英雄即使用共享等级及军械，英雄自身星级/技能保持独立。
- 旧档每个装备ID只折算一次；继承星级与退款预算守恒，重复迁移不重复入账。
- 多种种子验证早中晚合理配装；检查无治疗队选治疗玉佩确实没有凭空回血；更高品质不必在所有战术场景都最优。
- build、smoke、static-check及新增军械契约测试通过；UI离屏与真实Canvas审查、双平台关键路径验收。未完成战斗与迁移验证不得称整体已交付可玩。

本轮仅做设计文档与交互草案检查，不运行或更改正在并行实施的游戏功能。下一步优先确认“全队一套六槽”这项设计假设，再把默认数值调成正式实施表。
