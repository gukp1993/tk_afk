# 挂机定三国：轻负担挂机体验打磨实施方案 v1

日期：2026-09-26。核对代码基线：`920d1ae`。交付类型：**交给其他 harness 的执行规格；本轮未实施游戏功能。**

用户已明确：做挂机游戏，不希望玩家多考虑；暂不考虑美术，优先打磨玩法。本方案围绕这个定位展开。下述交互、状态机、任务权重是本版推荐实施规则；时间与成长目标是首轮测试目标，不是假称已经验证的平衡或留存结论。

开工先读根目录 `AGENTS.md`、`session_context.md`，再核对最新代码。默认 main 开发，不自行创建分支/worktree；其他执行者在途文件不能混入提交。既有英雄统一等级、军械共享方案继续有效。历史体验评审里的强制阵容解题、逐关换阵教学、肉鸽远征建议，不属于本版实施范围。

## 1. 这次要交付的体验

**上线收获 → 少量培养 → 一键自动出征 → 遇阻自动练兵后再试 → 暂时打不过就停下 → 离线积累后回来继续。**

玩家需要做的事情集中为：领取、选择想要的英雄、确认培养、开始出征。普通主线不要求频繁研究克制、调整站位或阅读战报；愿意研究的人仍可沿用现有编队功能。

首版必须区分两种“挂机”：

- **前台自动战斗**：停留在战斗页时连续运行；使用真实战斗引擎，胜利发玩家经验、战役奖励。
- **离线资源积累**：沿用现有12小时铜钱、招募令、精铁积累；不离线推关、不直接发玩家经验。退出游戏仍有资源收获，但主公等级不会因离线时间增长。

界面用“自动出征”和“离线收益”区分，不宣传“关闭游戏也在打关卡”。跨页面后台战斗、服务端挂机、离线战斗模拟不在首版中。

### 1.1 执行顺序

| 批次 | 必须交付 | 完成标志 |
| --- | --- | --- |
| A：能放心挂 | 自动出征、有限练兵恢复、连续练兵、非阻塞剧情、结算与生命周期保护 | 玩家点击一次后可连续过关，失败不会无限循环 |
| B：上线有事可收 | 免费一键收获、日常减负、单个近期目标、待选择奖励入口 | 不打塔/演武、不抽卡，也可完成核心每日活跃 |
| C：培养不费劲 | 改善现有推荐编队、直接打开培养目标、免费军械启用建议 | 不翻多个页面找奖励，不逐个试五个位置 |
| D：节奏验收 | 新号前20关、连续练兵、回流收获、旧档与长时间运行验证 | 有实际数据证明流程顺畅；定位并修复数值断点 |

A、B为首个可试玩版本的必需项；C随后接入；D贯穿各批，完成后才称“本版已验收”。每批可独立提交，不等待新增玩法。公会、真人PVP、新货币、专武、词条洗练、图鉴额外战力、体力和新广告位都不做。

## 3. A批：自动出征与练兵

### 3.1 入口和默认规则

- 主城原“出征”主按钮改为 **“自动出征”**；旁边保留 **“练兵”**，其首版默认启动一批连续练兵。
- 主按钮附近短说明：“遇阻自动练兵，暂时无法推进时停下”。不弹冗长设置向导。
- 战斗页保留手动单场模式，提供“本场后停止”和倍速切换；正常出征不收取次数或货币。
- 自动模式首次默认4倍速，之后记忆用户为自动模式选择的1/2/4倍速。旧手动模式保持已有默认，不因迁移擅自开启自动战斗。
- 自动运行不会替玩家升星、换阵、花精铁、抽卡、购买、选自选奖励、观看广告；无自动复活。
- 同一时刻只能有一个运行会话、一个战斗引擎和一个 `battle.pending`。

建议将参数统一放在 `utils/config.js`，值作为首轮默认：

```js
const AUTO_BATTLE = {
  defaultSpeed: 4,
  resultDelaySeconds: 1.5,
  recoveryLevelGain: 2,
  recoveryMaxWins: 10,
  recoveryMaxRounds: 2,
  trainingBatchMaxWins: 10,
  trainingBatchLevelGain: 2
};
```

这里的场次上限只约束一次自动恢复/练兵批次，不是每日次数限制。完成后玩家仍可再次点击练兵。参数必须经D批测试，不能散落在场景里。

### 3.2 战役状态机

状态最少包括：`idle / fighting / resultDelay / suspended / stopped / error`；同时保存当前模式 `campaign/training`、本次卡关号、恢复轮数、练兵轮起始等级、练兵胜场数、会话 token、当前战斗ID。

| 事件 | 行为 |
| --- | --- |
| 点击自动出征 | 验证有可上阵英雄；使用 `cleared + 1` 开局，不重打上一关 |
| 战役胜利并成功保存 | 收录实际结算摘要；等1.5秒；重读 `cleared + 1` 开下一关；清除本卡点恢复计数 |
| 战役首次失败 | 记录该关；未满级且有恢复预算则自动开始第1轮练兵；不盲目原地再战 |
| 一轮练兵开始 | 记录起始玩家等级L，目标等级 `min(L+2, MAX_LEVEL)`；重置本轮练兵胜场 |
| 练兵胜利 | 成功结算后检查：达到目标等级或已胜10场，就重试原关；否则继续练兵 |
| 第1轮后重试仍失败 | 开始第2轮练兵；同样最多升2级或胜10场后重试 |
| 第2轮后重试仍失败 | 停止自动出征；显示累计收获和“暂时受阻，收获材料提升后再出征” |
| 练兵失败、开局失败、结算失败 | 立即停止开新局，显示准确原因；不发失败经验 |
| 满级时战役失败 | 不进入练兵，停止并提示可培养英雄/军械 |
| 恢复练兵本场升级到满级 | 成功保存后直接最后一次重试原关；仍败则停止，不再练兵 |
| 胜利练兵收益为0 | 若开局时尚未满级则视为异常并停止；不得靠零收益战斗继续循环 |

练兵达到10胜而不足2级，只要实际获得过经验，仍允许重试一次；禁止因为未达目标继续突破上限。战役每个卡点最多3次挑战（首次＋两次恢复后重试），最多20场恢复练兵；胜利进入新关后重新计算。手动重新发起自动出征会开始新会话，属于玩家主动行为。

当前第120关之后已有循环关卡。本版保留其行为，不把120写成硬性终点；不编造第90/120关额外军械箱，也不删除已存在的后续关卡。

### 3.3 独立练兵

- 主城“练兵”启动一批，目标是相对批次起始等级提升2级，或完成10场胜利，以先达到者结束。
- 开始时显示“连续练兵 · 最多10场，升级后可提前结束”；使用与恢复练兵相同的真实引擎和结算。
- 失败一次、零经验异常、达到等级上限即停止；达到满级后禁用自动练兵按钮并明确“等级已满”。
- 不删除原有单场练兵能力；满级玩家仍可完成有效单场战斗/重战旧关做每日任务，但不再获得经验。
- 批次结束主按钮“自动出征”，次按钮“再练一批”。不自动无限串接训练批次。

### 3.4 时间、跳过和停止语义

- 沿用 `BATTLE.TICK` 固定步长，正常/倍速/跳过使用相同模拟规则。
- **自动调度绝不主动循环调用 `skip()`**。当前练兵无限且跳过可同步跑完整局，直接递归会形成瞬间刷等级的流程。
- 玩家主动“跳过”只作用于当前局；仍等场间1.5秒再开下一局，不记忆为“以后所有战斗都跳过”。不新增跳过货币或次数限制。
- 不在 `finish()` 内递归开启下一场，也不使用无人管理的 `setInterval` 刷战斗。由 `update(dt)` 消耗场间倒计时，每次最多执行一个状态转移。
- 1.5秒场间停留使用未乘倍速的前台 `dt`；4倍速只作用于战斗模拟，不把摘要停留缩成0.375秒。
- “本场后停止”：当前局正常完成和结算，不开下一局；在场间倒计时点击则立即停止。再次点击不会重复结算。
- “返回主城”：立即结束自动会话；未结束战斗中断无奖，已结算奖励保留。返回前有清晰文案说明当前未完成局不会结算，不另加层层确认。
- 每场开始重新读取玩家等级和属性；升级影响下一场，不改正在计算的单位。

### 3.5 剧情和奖励不打断

- 自动模式不自动打开每关剧情弹窗，也不写 `storySeen`。战斗页可点“本关剧情”；打开时暂停战斗和倒计时，关闭按原状态继续。
- 手动剧情看完/主动跳过仍沿用现有 `markStorySeen()` 语义。仅展示一行摘要不等于看完剧情。
- 战斗期间的剧情入口不导航去另一个会重启战斗的场景；使用现有IMGUI弹层。
- 普通结算显示短摘要并自动继续。章末奖励、新军械和升级可突出一条文字，不强迫点确认。
- 首胜三选一、英雄自选券、军械自选箱都保留现有待领取/库存权益。自动模式只提示“获得自选奖励，回城可领取”，不代选，也不暂停整条自动流程。
- 会话结束显示：推进的关数、等级前后、实际经验和资源增量、新解锁军械、获得的自选权益。摘要只是已入账结果展示，不能再次 `applyReward`。
- 摘要按结算ID去重，战役基础奖励与 `reward.chest` 分开累计，军械重复精铁也计入。第10关的SR券目前不在普通 `reward` 对象中，需给统一结算摘要补明确的“已发权益”字段，不从猜测关号再次发券。
- 会话统计只保留聚合数值与最近少量展示项（建议最近10条），防止长时间挂机事件列表无限增长；已入账资产持久化，会话画面摘要不要求跨重启恢复。

### 3.6 前后台、导航、保存

- `onHide`：显式挂起当前战斗和场间倒计时，保存；即使平台后台仍触发帧也不推进逻辑。
- `onShow`：重置帧时间基准，显示“自动出征已暂停 / 继续”；玩家点继续后才恢复同一内存战斗。后台经过多久都不补算战斗、经验或过关。
- 普通剧情关闭可自动恢复；因切后台挂起必须显式点继续。两种暂停原因分开，关闭剧情不能误解除后台暂停。
- 切换页面或退出战斗使会话 token 失效，停止调度；清理当前匹配ID的未结算 pending。`switchTab`、`pop` 和战斗页上方再 `push` 新场景都要处理，不只靠当前 `onExit()`。
- 从新场景返回时不得触发无参 `battle.onEnter()` 重开战斗；若栈内保留已退出的战斗实例，只显示已停止摘要（无完整结算时显示“本场已中断”）与返回主城/重新出征按钮，不恢复旧引擎。统一区分首次进入、恢复和退出，对现有其他页面导航行为做回归。
- 进程重启：保留已提交资产，沿用现有规则清理未结算 pending；不恢复自动会话、不重新发中断局奖励。
- `settleBattle.ok=false`：停在当前结果待保存状态，提供重试保存/退出，不开下一场覆盖 pending。重试使用同一ID与冻结的战斗结果。
- 开局与中断也须有事务边界：`beginBattle()` 修改序号/pending后若保存失败，回滚并返回 `ok:false`，不创建引擎；`interruptBattle()` 保存失败同样回滚并报告错误。即使清理失败，已退出会话的token仍失效，不得继续跑旧引擎或放任新局覆盖未清理pending；重试清理成功后再开新局。
- `alreadySettled=true` 可恢复展示，但不能重复累加会话统计或每日计数；旧ID延迟回调不能改变新ID的状态。
- 同一ID的成功settled事件也只能被状态机消费一次：去重同时覆盖摘要、练兵胜场、恢复轮数、倒计时和下一动作。使用当前ID与已处理标记即可，过期ID直接忽略；不要为了去重无限保存全部历史事件。
- 日切检查在有效战斗结算前和聚合领奖前执行。跨午夜的战斗按结算日计算日常进度；重复提交已结算ID不得把昨天战斗再计到今天。

## 4. B批：一键收获与日常减负

### 4.1 主城免费“一键收获”

替换现有主城普通领取按钮，明确领取范围：“离线收益＋已完成日常”。顺序固定：

1. 检查日切；结算截至本次点击时刻的挂机资源。
2. 有任一整数资源可领时，按普通倍率领取；空桶不增加“领取挂机收益”任务次数。
3. 领取全部已完成未领取任务。
4. 重新计算活跃，领取全部新达标未领取宝箱。
5. 成功保存一次，返回统一到账明细；无可领取内容则返回无变更结果。

新接口应作为一次事务操作：先快照/在副本计算，持久化成功才返回成功；失败恢复内存，不展示已领。不得由页面直接逐项改余额。若复用现有 `claimIdle/claimQuest/claimActiveChest`，须在store内部编排并确保没有中途保存的半成品。

允许任务弹窗单独提供“领取全部日常”，共享同一日常领取逻辑。单项领取继续可用，也需立即可靠保存。整数发放、小数保留规则不变，频繁领取不能吞掉招募令/精铁余数。

不纳入一键收获：自选英雄、自选军械、抽卡、精铁解锁、元宝购买、广告双倍。广告入口继续独立；免费领取后当前桶已减少，不能给同一份资源再补领双倍。

点击后用一条可关闭的汇总展示实际获得资源；不为每项任务连弹窗口。资源不够时按钮显示“收益积累中”；有日常可领而离线桶为空时依然可点。

### 4.2 核心三项即可满活跃

保留现有任务ID、任务奖励和40/70/100宝箱奖励，仅改以下计数语义与活跃权重：

| ID | 新显示名称/条件 | 活跃 |
| --- | --- | ---: |
| `q_idle1` | 领取一次实际非零挂机收益 | 30 |
| `q_battle1` | 任意有效战斗胜利1次 | 30 |
| `q_win3` | 任意有效战斗胜利3次 | 40 |
| `q_summon1` | 点将1次，沿用 | 20 |
| `q_arena1` | 演武切磋1次，沿用 | 20 |
| `q_tower1` | 完成1次群英塔战斗，胜败均可，撤退不计 | 15 |

“有效战斗”指经过引擎终局并经 `settleBattle` 首次成功提交的战役、练兵、塔、演武；重复结算、中断、主动撤退不算。将 `q_win3` 从 `winCampaign()` 移至统一胜利结算，将 `q_tower1` 从 `winTower()` 移至塔战终局结算，避免双记。

“实际非零挂机收益才计q_idle1”在底层 `claimIdle()` 统一校验，覆盖旧单项领取和广告双倍入口，不只在一键收获外层过滤。

核心循环“领一次挂机＋三场练兵胜利”即可100活跃；点将、演武、塔是额外可选任务，也可替代部分核心任务。全部任务合计155，活跃进度条视觉封顶100，原始积分照实计算，超过100不额外发宝箱。

现有 `activePoints()` 按已领取任务计算，故一键操作必须先领任务，再领宝箱，不使用点击前的旧活跃值。

这是明确的获取门槛调整：尤其每日80精铁更容易拿到，不能声称经济完全不变。保留旧档当天所有 `quests/claimed/active`；权重更新后允许领取新达标且未领取的宝箱，但已领宝箱绝不重发。不重置玩家当天进度。

### 4.3 主城只突出一个近期目标

新增只读 `getNextGoal()`，返回 `id/title/progress/rewardPreview/action`，由真实状态派生，不能附带领奖副作用。主城最多显示一张目标卡，优先级固定：

1. `firstWinChoice().available === true`：提示“首胜奖励可领”，直达现有三选一；不是再发一次卡。不能仅凭尚未领取就把未胜首关的新号当成可领。
2. 上阵英雄满足升星条件：提示某个可升星英雄，直达其升星预览；同分按当前阵容槽位，避免每帧跳目标。
3. 有军械自选箱或英雄自选券：显示一个待选择奖励，直达对应选择面板。军械先低品质后高品质，英雄先SR后SSR；不限制玩家从其他入口选别的。
4. 有已解锁、可免费严格提升的军械：提示“可启用新军械”，按C批规则给出建议。
5. 其余显示最近章末奖励：“再过N关，获得章末奖励”；第10/30/60关附带其实际自选权益，通关后自动更新。

首胜领取后仍可从英雄页继续培养；不做不可关闭的新手强制指引。所有提示只导航，不能自动消费或承诺“点一下必过关”。

章末奖励和自选里程碑先收口为共享配置/只读奖励定义，让发奖与预览消费同一份数据。第10关显示应区分：本关常规奖励、章末额外100元宝＋1招募令、该Boss关自身1招募令、SR自选券和R军械箱；不把两张招募令重复加成四张。

第120关后继续按当前循环战役显示下一章末目标。资料里未定义的特殊奖励不显示。满级时不推荐靠经验升级；满星不推荐升星；已有物品不显示为待解锁；缺进度门槛时不能只写“精铁够了即可解锁”。

推荐的UI参数契约（新增，不是现有能力）：

- `app.switchTab('heroes', { focusFirstWin: true })`：打开首胜奖励；需显式扩展 `switchTab` 的params传递。
- `app.push('heroDetail', { id, focus: 'ascend' })`：定位现有升星预览，沿用当前英雄ID参数规范。
- `app.push('armory', { boxQ })` 或 `{ slot, itemId }`：初始化对应选择/详情，不在 `onEnter` 立刻重置掉目标。
- `app.push('shop', { pickRarity: 3 })` / `{ pickRarity: 4 }`：使用已有库存SR/SSR券。当前集市只是显示券数，选择弹层主要由购买触发；新增独立“使用自选券”入口并复用该弹层，不能要求再购买一次才能用库存券。入场校验对应券数量，取消不扣券。

上述路由名称/参数实施前逐项核对，统一更新调用者与目标页。不要跳到页面后还让玩家自己滚动寻找目标。

### 4.4 收获和成长反馈

- 一键收获显示实际获得资源；升级显示“主公Lv.X→Y，全体武将同步提升”；英雄升星显示前后星级与真实战力变化。
- 军械启用/升星显示“全军生效”与真实属性前后值，不能把装备加成提升10%写成英雄总攻击提升10%。
- 新解锁图鉴和获得自选奖励有简短提示即可，不卡住自动战斗。
- 当前 `fastReward()` 不发精铁，招募令按现有2小时公式取整为0。本版不顺手加奖励，文案改为实际奖励预览，例如“快速收获铜钱”，不能声称得到完整2小时全部挂机资源。
- 不给随机SSR同名卡标注“明天一定能升星”。资源等待估计如实现，必须计入现有余额/未领资源和12小时容量；900精铁不能显示成一次离线75小时可全收。本版可直接只显示缺口，不做时间估计。

## 5. C批：少量培养操作

### 5.1 改善已有“一键布阵”

首版采用可解释、确定性的“均衡推荐”，不做每关解题、不宣称最优战力或必胜：

1. 从已拥有武将中取战力最高的坦克；无坦克时取最高战力战士，仍没有则用最高战力英雄。
2. 从剩余武将中取战力最高的辅助（若有），剩余名额按个人战力降序补齐到5人。同分按英雄ID排序。
3. 布位时坦克、战士优先放前排，辅助优先后排；缺前排时其余英雄按生命降序、同生命按防御降序、再按战力降序/ID升序补齐，保留辅助后排优先。每人只占一槽，排序写在纯函数中，不使用随机数。
4. 不足5人填实际拥有的人，其余空位；全空时给出招募/已有奖励入口，不启动战斗。

推荐按钮展示替换名单并允许一次点击应用；保留当前编队和自由换人。抽到新英雄不自动换阵；卡关不会擅自重排。使用 `recommendFormation` 纯计算与 `applyFormation(ids)` 原子校验/保存，不能逐槽修改到一半后报错。

这是轻量启发式。用初始五人和几组不同收藏回归；若明显劣于原推荐，修正规则再交付，不用个人战力增加当作实际胜率提升的证据。不为满足推荐而改英雄稀有度/技能/抽卡规则。

### 5.2 军械免费启用建议

- 首版只推荐N/R/SR之间同槽向更高品质替换：已解锁、无特殊效果差异、每个基础属性不降低且至少一项提高；同槽取最高符合项。
- 已启用SSR的槽不动，SSR之间的效果取舍仍由玩家选择。推荐不等于自动解锁/花精铁。
- 显示待替换的部位和全军属性变化，点击“启用推荐”一次应用并保存；不把图鉴奖励自动装备，不自动升星。
- 部位星级保留，英雄数量不影响消耗。没有符合项时隐藏建议，不重复红点。
- 英雄/军械升星仍用现有成本预览，主城目标可直接定位；本版不做“一键花光所有培养资源”。

## 6. 成长节奏：首轮测什么、如何调

### 6.1 已核对的经济基线

| 条件 | 确定可得/可花 | 用途与注意 |
| --- | --- | --- |
| 新号 | 五人阵容、10万铜钱、1888元宝、12招募令、60精铁 | 不抽卡也能开战；60铁足够一个部位0→1星 |
| 首关胜利 | 初始三名SSR同名卡三选一 | 选后花2000铜钱可完成首次英雄升星，是早期明确成长点 |
| 第10关首通 | SR英雄券、R军械箱＋正常章末/关卡奖励 | 第30/60关分别有SR/SSR军械箱 |
| 连续积累12小时 | 144精铁、3招募令；铜钱按进度 | 通10关时铜钱速率7300/小时，12小时87600 |
| 只做核心日常并领取 | 80精铁、30000铜钱、50元宝、2招募令、30碎片 | 含核心任务与三档活跃箱，不含挂机、战斗本身及可选任务奖励 |
| 定向解锁军械 | R/SR/SSR耗100/300/900铁，并受10/30/60关门槛限制 | 不增加英雄保底 |
| 单部位升满5星 | 1860铁、62000铜钱 | 六部位共11160铁；不把一次离线当作可毕业 |

上表核心日常铜钱合计为30000、元宝50，精铁80、招募令2、碎片30；不含挂机本身、不含战斗结算奖励、不含可选任务。未改这些单项奖励。

军械白兵刃0→1星：该部位攻击贡献从2%到2.2%；初始全军攻击军械合计4%，因此相对攻击约提升 `0.002/1.04 ≈ 0.192%`（取整前）。它不应承担“升一下立即连过几关”的宣传。玩家等级提升、首胜英雄升星、阶段性新军械共同构成成长。

### 6.2 首次体验目标

以下为需要通过试玩/模拟检验的目标，不是硬编码到关卡里的保送规则：

| 体验段 | 目标 |
| --- | --- |
| 第一次进入 | 一屏找到自动出征；不需要先研究五名英雄、不需花元宝/看广告 |
| 前3场 | 没有必点剧情或逐场领奖；自动推进不中断 |
| 前10分钟 | 能体验首胜奖励→一次英雄升星→继续自动出征；单次培养跳转不超过3次点击，不含自选列表滚动 |
| 前20关 | 初始队＋确定可得培养，不依赖随机抽中某将；至少验证可通过有限练兵或确定培养继续推进 |
| 短时回流 | 两次主要操作即可领取已积累收益并开始自动出征；培养有需要再做 |
| 日常 | 一次非零挂机领取＋任意三胜，可拿满核心活跃；无需去塔、演武或召唤 |

不要求回流每次必定过关，也不伪造战力增长；不要求5分钟打穿20关。记录真实耗时与卡点，避免把“快刷关”和“有长期目标”同时写成无边界要求。

### 6.3 数值调整顺序和范围

1. 先完成自动与减负流程，**保留现有XP、敌方强度、军械属性与成本**跑基线，记录首卡点与自动恢复耗时。
2. 若新手连练兵都不稳定获胜，优先校准练兵敌方系数；若某一早期关形成断崖，优先调该关/章的可配置强度，而非要求玩家抽特定SSR或看广告。
3. 若无操作等待过长，先核实真实4倍速、场间延时与剧情是否生效，再调战斗/经验节奏；不能用循环 `skip()` 掩盖问题。
4. 若持续多轮数据表明军械培养反馈过弱，提交明确的属性/成本试算对照；本规格不预先推翻刚实施的共享军械公式。不要用夸大文案或强制红点掩盖低收益。
5. 把必要的平衡调整集中到配置，并附修改前后相同测试样本的数据。改变玩家经验来源、概率/保底、等级上限、离线容量、货币体系、军械星级公式等既定规则不在该调参权限内，应另列方案。

首版不新增日历签到或七日任务。先把已有首胜、第10/30/60关、每章宝箱做成看得见的目标，避免制造第二套奖励和更多红点。

## 7. 主城与战斗页布局要求（占位UI）

主城保留当前建筑入口与五栏导航；本版不用重画整座城。优先固定区域：

1. 顶部：主公等级、经验、现有资源。
2. 当前章/关与一张近期目标卡。
3. 主操作“自动出征”，次操作“练兵”。
4. 收获区：实际积累资源简述＋“一键收获”；“加速/双倍”仍为次入口。

战斗页显示：当前关、自动状态（出征/练兵恢复第几轮）、等级进度；“本场后停止”“倍速”“跳过本场”“本关剧情/返回”。练兵明确“不消耗次数，胜利获得经验”。不用堆叠完整战报。

结算摘要与目标详情允许滚动，按钮固定在弹层可用底部。按375×568/667/812检查，短屏不得挤掉停止/返回按钮。控件仍走 `src/ui.js`，不在页面直连触摸事件或平台API。长名称、多奖励、全部满级等状态不溢出，不产生无法关闭的模态。

## 8. 存档与资产约束

- 当前主存档v5。本版只新增可选设置字段（如 `settings.autoBattleSpeed`），缺省给默认值；不需要为纯设置无理由再迁移全套英雄/军械。
- 不持久化可自动恢复运行的 `autoEnabled`；加载存档绝不自行开打。会话状态、场间倒计时、引擎实例只在内存。
- 近期目标完全派生，奖励仍使用现有 `heroProgress`、`vouchers`、`armory.boxes/claimedMilestones`、`daily.claimed/active`，不建第二份“已领状态”。
- 聚合领奖、编队批量应用、免费军械批量启用需要成功后立即保存；失败回滚。旧档任何已有阵容、星级、物品、未选权益不因打开新页面而改变。
- 本版引导到的首胜选卡、库存券使用、英雄升星也必须成功即保存；核对现有 `claimFirstWinChoice/useChoiceVoucher/ascend`，不能仍仅依赖10秒心跳。选择取消无变化，保存失败恢复券、卡数、铜钱及星级。
- 精铁、招募令的小数只留在挂机累计中，余额仍整数；新增汇总不能四舍五入产生资源。
- 真实设备档不可用来跑自动化实验；Node测试使用内存平台桩和合成旧档。

## 10. 验收用例与交付证据

### 10.1 自动流程

- 连胜3关无额外点击；每局ID不同，关卡只推进一次；结算保存成功后才开下一局。
- 首次战败进入练兵，达到2级/10胜条件后重试同关；两轮均失败后停机；成功则重置卡点预算。
- 练兵失败、空阵容、满级、零经验、保存失败均停机且有正确原因；没有无限重试。
- 玩家199级时恢复练兵升至200后只重试原关一次，失败停止；独立练兵升至200直接结束。
- 停止与终局同帧、跳过与终局同帧、连续点击、过期回调都不双开战斗/双发奖。
- 场间等待重复投递同一settled事件，练兵胜场、恢复轮数、倒计时和下一动作均不变化；开局/中断/结算保存分别注入故障，核对回滚与停止。
- 自然结束、倍速、手动跳过对同阵容/种子产生一致结果；自动逻辑不额外调用随机数影响战斗。
- 切后台期间引擎时间、等级、关卡不变；前台不追赶；点继续恢复；切页面停止；重启不恢复未结算局。
- “战斗→其他场景→返回”完整往返只展示已停止状态，不重开、不续跑旧局。
- 剧情不阻塞自动，未阅读不标已读；主动阅读暂停；后台回来关闭剧情不绕过暂停。
- 自动运行不扣元宝/精铁/招募令、不看广告、不自动替换阵容或消耗自选券。

### 10.2 收获、任务和目标

- 挂机有整数收益＋三场练兵胜利后，一次领取全部达100活跃并发三档宝箱；无须其他模式。
- 战役胜利只计一次q_win3；有效塔败北计挑战，撤退不计；重复结算不加任务。
- 跨午夜结算、跨午夜领取、当天已领部分/全部宝箱、权重改变旧档均不丢进度或重发。
- 一键收获包含本次挂机领取刚完成的任务及其解锁宝箱；空桶且无任务无副作用；重复点击不重发。
- 保存故障注入后资产和已领标志回滚；成功重试只到账一次；奖励摘要等于实际余额增量。
- 第1/10/30/60关权益分别一次；自选奖励取消后仍在；目标预览与结算相符；超120关显示真实循环目标。
- 新档、旧档、满级/满星/图鉴全齐、资源差1、只有1名英雄/空阵容、有未领自选权益均有合理界面。
- 目标按钮到达可执行位置；推荐只用已有英雄和解锁军械，不替玩家消费；没有同品质SSR自动换装。
