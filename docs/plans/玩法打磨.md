# 玩法打磨（多轮循环）

状态：实施中（第一轮）
适用平台：微信小游戏（Web 构建仅本地预览）
负责人/维护者：zcode（本轮执行者）
更新日期：2026-09-28
代码基线：commit `295ad2e` 后的 main（存档 v7，30 天仿真 90% 通关、P50 第 22 天）
决定来源：用户 2026-09-28 指令——"不关注美术，从玩法上打磨；原来的规则不合理可以废弃；可以借鉴互联网项目；开发完成后让其他 agent 体验、给反馈、继续修改；不喊停就一直继续"。用户未逐项确认本方案数值，按该授权直接实施，逐轮以 200 种子仿真与试玩代理反馈校准。

## 1. 目标与玩家体验

目标玩家：每天上线一次、单次会话 10~15 分钟的微信轻度玩家；第一期以主线 12 章/120 关 + 约 30 天通关为锚。

打磨方向（不涉及美术）：
1. **反馈感**——失败可读（输在哪、差多少）、抽卡有盼头（保底进度）、胜利有增量（推图改变收入）。
2. **目标感**——七日目标、塔/演武与主线耦合、羁绊收集，消除"第 7 天后无事可盼、第 23 天通关后 7.7 天空窗"。
3. **假规则治理**——演武伪选择、N/R 碎片死循环、铜钱 98% 沉没、练兵无限刷级等"存在但无意义"的规则，改造或退役。

## 2. 已核实的现状

三份证据报告（2026-09-28，子代理产出、主执行者复核关键数字）：
- [数值体检](../reviews/数值体检-2026-09-28.md)：90% 通关、82% 败仗是超时、铜钱 98% 沉没、广告零增量、等级第 25 天触顶、难度墙只转移不消失。
- [玩法审查](../reviews/玩法审查-2026-09-28.md)：敌方全阵容 +18% 同阵营光环（玩家不可见）、练兵无限刷级、repeatGold 指数残留、败北零诊断、演武伪选择、碎片陷阱等 10 问题 + 死代码清单。
- [竞品机制对标](../reviews/竞品机制对标-2026-09-28.md)：保底/积分池/七日目标/悬赏/周结算/神秘商人/阵营试炼/迷宫 10 机制排序与实现成本。

补充（主执行者蒙特卡洛，300 次）：按当前抽卡量（55~70 抽/日、无保底），N/R/SR 池中位第 5/12/16 天集齐，之后 88% 抽取结果为满星将的 1 碎片；SSR 全集中位 45 天（30 天窗口外）。

## 3. 范围与不做项

只改：`utils/` 规则源、`assets/scripts/` 页面交互、`test/` 仿真与冒烟。存档只加字段（normalizeState 兜底），不升版本号；不改四档抽卡概率、不动元宝/精铁挂机速率与额度（用户既定经济锚），不动六槽满星 30 天预算（第三轮若加章末精铁奖励需重估并说明）。

不做：美术与立绘、排行榜/公会/任何需要服务器的功能、付费点、抖音平台、真实广告接入。

### 第二轮：目标感与耦合（待第一轮验收后）

1. 七日目标：`SEVEN_DAY` 第 1~7 天奖励（d1 招募令×3+元宝100，d2 元宝300，d3 招募令×5，d4 精铁200，d5 SR 自选券，d6 元宝888，d7 SSR 自选券）；`state.sevenDay={start,claimed[]}` 首登锚定；主城入口+弹层。

3. 演武：令牌按 diff 2/3/4；段位首达一次性奖励（元宝100+精铁50，`state.arena.rankReached`）。
4. 练兵：经验每日上限（每日前 20 场练兵全额、之后 0）；战役/塔败北给 25% 经验。

## 5. 实施顺序

每轮一个可独立验证的提交：
1. 规则改动落 `utils/`（config 集中数值）→ `node scripts/cocos-sync-domain.js --check` + TypeScript 检查。
2. `test/smoke.js` 增补断言 → `node test/smoke.js` 全过。
3. `node test/simulation.js` 200 种子对照，结果与结论追加到 `docs/reviews/玩法打磨仿真对照.md`。
4. 页面改动（如该轮涉及）→ `./scripts/cocos-build.sh web-mobile` + 无头浏览器新档链路冒烟。
5. 派发试玩代理（无头浏览器实玩 + 规则视角评审）→ 反馈入下一轮清单。
6. commit（一次一轮）+ `session_context.md` 交接 + push。

## 6. 验收标准

- 自动：镜像检查、TS 检查、smoke 全过；200 种子仿真达到该轮验收数字；`git diff --check` 干净。
- 页面：web-mobile 无头浏览器新档链路（建号→战斗→召唤含保底显示→败北诊断→关卡预览徽记）无控制台错误、无遮挡错位。
- 边界：旧档（v7 无新字段）加载回填默认值且行为正确；时钟回拨后当日不重置（第二轮起）。
- 未测项不写成已验收；真机与微信开发者工具实点仍按 `docs/reviews/acceptance-checklist-30d.md` 归用户/后续轮。

## 7. 风险与开放问题

- 保底 40 抽是倾向值（30 太快/60 太慢之间取中）；若仿真显示通关率 >98% 或 SSR 满星线 30 天内大幅推进，回调到 45~50 或减十连保底。
- 敌方光环减半后 normalOverrides（72/89/99/117 与名将削峰）可能过度补偿，仿真对照后决定是否撤部分补丁。
- 残局狂暴改变战斗手感（双方 60 秒后互相加速斩杀），真机体感待试玩代理与用户复核。
- 每轮数值只对"每日一次参考玩家"校准；投入型玩家在练兵上限（第二轮）落地前仍可超速，属已知失真。
- 多 agent 并行纪律：`utils/config.js`、`utils/store.js`、`assets/scripts/CocosBootstrap.ts`、本文件、`session_context.md` 为热点文件，由本轮执行者统一收口。
