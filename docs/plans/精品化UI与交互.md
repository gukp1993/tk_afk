## 1. 目标与玩家体验

玩家打开游戏应看到可探索的三国城镇，进入战役能识别当前路线及真实出战武将，战斗中能辨认英雄与双方状态；招募操作在招贤殿主视觉下清楚区分单抽/十连与消耗来源。页面装饰应衬托人物与操作，不能让每个资源、小行和主按钮都具有相同视觉权重。

例：新号从主城点将台进入召唤，选择招募令十连，确认消耗并看到现有逐卡揭示；打开万能卡后可滚动选到最后一名未满星 SSR，广告和导航均不能抢走弹层输入。

本方案是当前主题唯一任务表；原型以首批真实 Cocos 页面与状态截图表达，不另造无法复用的 HTML 游戏壳。截图和生成提示词见 [原型目录](../prototypes/精品化UI/)。

## 2. 已核实的现状

视觉、交互两名独立 agent 已读现行源码并核对 Web 实拍：40 张透明 Q 版武将（16 SSR+24 SR）、5 张全屏背景、5 张通用 UI 皮肤；icons 目录无实际图。现有逐卡揭示、BattleFx、面包屑与残影修复均存在，不重新从零立项。

- `Scenery.cityMap/campaignMap` 的不透明底覆盖页面背景，大部分玩家可见区仍是几何占位。
- `BattleScreens.drawFighter` 为姓氏字卡，边框按站位而非英雄品质；规则 snapshot 尚未携带已有的 heroId/faction/cls。
- `HeroScreens.summon` 的招贤殿大区只有圆环将字，四操作权重相近；底部留有较大空黑。
- 万能 SSR 弹层无滚区；16 目标可复现第9行与取消重叠、后续行越框，广告绘制在弹层上；万能卡标题不在面板内。4星目标被 `<4` 条件过滤，但配置 SSR 满星为5，属界面资格缺陷。
- 玩法页四大卡后连排大量窄条，入口、收益、周任务缺少清晰分组。
- 英雄工具区占首屏约376px，可收紧80px，保留卡面尺寸与筛选排序。
- ArtService 已支持微信分包；指南“零图片/不支持分包”等历史文字不作为本次事实。

## 4. 设计规则

1. 视觉方向：温暖Q版三国，墨绿、朱红、少量暖金；美术细节优先集中在场景、人物和核心操作。大容器/主按钮可描金，资源行、普通列表、次级按钮减装饰。
2. 720×1280设计坐标；普通页面内容不得占导航上沿-548以下。新布局先列空间预算，整页大调整采用滚区。
3. 主城美术楼宇与可点入口匹配；同页只保留固定出征/领取区，点击热点不得相互盖住。
4. 战役地图五个点按实际美术的CAMPAIGN_ART_ROUTE校准，缺图使用原CAMPAIGN_ROUTE，不改变关卡或解锁；军营五槽使用已配置id对应立绘。
5. 战斗原FighterGlyph动画根保留，立绘、框随同动；名字、血怒条继续独立可读。bg_main使用竖屏构图，避免横图拉伸；缺图回退。
6. 召唤四种招募来源均保留，十连两个主CTA；概率与保底来自配置。万能卡弹层最后绘制、定高滚区、关闭后才恢复底导航。
7. 小货币/导航图进入resources/art/icons；场景与人物进入art-heroes分包。imagegen原始输出留原位置，工程保存可运行压缩资产与提示词；新图不覆盖旧资源。
8. 首批不全量增加120大纹理。当前loadDir整包预载存在内存扩张风险；后续80将前需做按需加载/头像方案，不能仅凭压缩文件体积判设备纹理占用。

## 7. 风险与后续批次

- 新图在真实控件遮挡后可能出现热点偏移、脸部裁切或文字对比不足，必须实拍后修。
- 主包接近4MB（历史3620KB），图标需缩尺寸并测最终产物；场景一律分包。
- 全包预载和背景纹理的设备内存需真机检查；后续R/N补图前完善按需加载，不盲目堆全量资产。
- 第一批后顺序：首发阵容缺图（廖化/孟达）→剩余货币/功能图标→集市商品视觉/次级页面→按需加载后补R/N→效果/音效/真机细节。每批照常文档更新、截图、回归和提交。
