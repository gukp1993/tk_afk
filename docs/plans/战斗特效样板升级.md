## 目标与玩家体验

保持自动战斗结算不变，让普通攻击、治疗和 SSR 必杀技在小人战场中更像明确的动作事件。玩家能看清谁出手、攻击往哪去、何时命中、技能影响哪些目标。普攻演出短促可读，大招更强且更有仪式感，但不长期遮住角色、血条和操作区。

样例：关羽挥出金玉弧光并突进，命中时敌方闪现冲击火花、受击反馈与伤害数字同步；弓将射出带尾迹的箭光；治疗触发翠绿环光和上扬灵粒；关羽释放 SSR 必杀时，战场略微压暗，青龙主题能量卷过画面并在目标命中时爆开，随后恢复战场。

## 已核实的现状

- `assets/scripts/services/BattleFx.ts` 已消费 `step().events`，支持近战突进、远程/法术/治疗/格挡光效、命中抖动、飘字、SSR 主题大招场景、队列上限及跨场清理；战斗逻辑与表现层已分离。
- `assets/scripts/screens/BattleScreens.ts` 使用全身静态立绘与血条/怒气条；目前没有 Spine 动作、战斗粒子图集或专用序列帧资源。主要光效仍由一次绘制的 `Graphics` 几何形状构成。
- `assets/scripts/services/ArtService.ts` 启动时通过 `resources.loadDir('art', SpriteFrame)` 加载 `assets/resources/art/` 下资源并以 `SpriteFrame.name` 建 key；战斗背景和英雄立绘另从 `art-heroes` 微信分包加载。
- 参考放置卡牌作品只提取节奏、层级、技能归属和命中可读性原则。所有人物、纹样和特效图案使用原创资源，不复制其他游戏资产。

## 范围与不做项

首批做 4 个可复用样板：

1. 战士近战刀光与共享命中冲击素材。
2. 弓手远程箭光/拖尾。
3. 医将治疗环光与轻粒子反馈。
4. 关羽 SSR 青龙主题全屏演出。

复用现有 `BattleFx` 事件、队列、时钟、目标寻址、倍率与清理机制。只改表现和资源加载，不改 `utils/`、技能数值、存档、页面操作和结算时序。角色仍用当前立绘配合位移；Spine 角色重制、其余英雄主题、录屏式大招动画和高成本屏幕后处理留待本轮验证之后评估。

新贴图遵循现行资源接入规定，放入 `assets/resources/art/fx/` 并由 `ArtService` 启动预载；资源名固定使用 `fx_slash`、`fx_projectile`、`fx_impact`、`fx_mend`、`fx_guanyu_ult`，导入和运行时查询均核对 basename key。所有 5 张图压缩后合计 ≤250 KB，为微信小游戏主包 4 MiB 上限留出余量。未加载或不存在时回退当前 Graphics 效果，不阻断开战。

## 视觉与交互规则

- 普攻表现沿用现有释放/命中时钟：`act` 触发出手，命中段对齐 `hit` 飘字与目标反馈；动画使用同一个 `dt × speed` 时钟，切倍速时同步加速。
- 关羽大招沿用 SSR 队列：短暂压暗、青龙贴图聚焦旋入、命中亮闪与波纹、淡出恢复；规则即时结算，表现不得阻塞战斗推进。队列和大招最长尾播预算保持有界。
- 治疗使用青绿/玉色，命中冲击使用金白/阵营点缀色；图层绕开操作 HUD，角色和关键状态保持可辨。
- 粒子数量、贴图尺寸与同时活动效果有明确上限；页面重绘、切换战斗倍率、离开战斗、角色死亡和连续大招后都必须正确回收节点。
- 采用轻量 Sprite 贴图加 Cocos 节点变换/透明度动画作为首批；仅在确有收益时使用粒子，不叠加全屏高成本 Shader。

## 验收标准

- 人工视觉抽样（Web 录屏，需记录样本数和截图/录屏位置）：观察至少 20 次近战、20 次远程释放、10 次治疗和 5 次关羽 SSR。轨迹方向须与目标一致，冲击、飘字和受击反馈在同一命中段出现；治疗不被误看作伤害弹道；SSR 青龙主题可辨且结束恢复战场。样本数是视觉抽样口径，不是 smoke 自动断言。
- 集成行为检查：连续双大招仍受限排队；加速后收尾；施法者死亡、页面重绘或离场按现有路径清理，不留半透明层。通过 `__tkDiag()` 与页面节点观察记录，若不能可靠注入某事件则标未测，不伪造样本。
- UI 可读性：两种手机视口中角色、血条、怒气条、伤害数字和战斗操作均可辨；大招期间不持续遮挡关键战场信息。
- 自动化：规则镜像检查、Creator TypeScript、现有 smoke（仅规则回归）和 `web-mobile` 构建通过；无 `utils/`、存档或结算时序 diff。微信目标包构建成功并记录主包体积；视觉同步和可读性必须另由实战观察证明。
- 设备体验目标：微信真机常规战斗保持 ≥55 FPS、无肉眼可见卡顿；若设备未能实际运行，此项标“未验证”，不得声称通过。

## 风险与开放问题

- 当前角色 PNG 无可驱动骨骼。此批效果可以让出手更有冲击力，但不会替代真实挥剑/拉弓姿态；验证后再决定是否为主力英雄制作 Spine 动作。
- 战斗 FX 按仓库资源接入规定放在 `resources/art` 主包中；如果实际微信包超出 4 MiB 或低于预留空间，不得偷偷移入 art-heroes，应先压缩/减量资源并记录用户现行资源规则下的取舍。
- Web 实拍不能代表微信机型的粒子成本；如微信真机设备尚未接入，本轮只能标记为“代码与 Web 样板已验证，设备待验收”。
- 关羽作为首个 SSR 样板是视觉验证选择，因为当前主题已定义为青龙；样板通过不自动等于其余 15 名 SSR 已达到同等品质。
