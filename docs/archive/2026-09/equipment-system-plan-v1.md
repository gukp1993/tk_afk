# 装备系统完善方案 v1（提案）

日期：2026-09-26；运行代码核对基线：19343f0。范围：装备获得、穿戴、强化、回收、定向打造、属性结算与旧档保护；不做美术、不实施游戏改动。

**状态：需求方案已交付，供讨论，尚未成为产品决定。** 本文建议的赠送、材料、返还、获取节奏和后续套装均未实现；示例数值没有经过平衡验证。现有英雄120将、四档招募概率和无保底规则不变。已有英雄系统提案也未获本轮实施授权。

## 1. 装备系统要解决什么

玩家需要理解五件事：装备有什么用、从哪里获得、先给谁、如何变强、换装备会不会白养。

推荐第一版：**每将四槽、四档品质、确定强化、免费换装、培养投入可回收、随机掉落与定向获得并存。** 先让五人队的20个装备位运转起来，之后再做套装和高阶进阶。

完整循环：推关/挂机 → 获得装备与材料 → 给主力穿戴 → 强化或补缺件 → 再次挑战 → 换下的装备给替补或回收。卡关时仍能从挂机获得材料，不能要求先打赢才能获得打赢所需的全部资源。

第一版的策略来自资源分配：前排撑不住先加强铠甲/头盔；输出不够先加强主输出兵刃；治疗者容易阵亡先补生存，治疗随攻击成长的技能也能受益于兵刃。装备支持英雄职责，英雄技能继续决定独特玩法。

## 3. 现有代码：可保留的基础与必须补齐的问题

已实现：

- 四槽：兵刃加攻击、铠甲加生命、头盔加防御、战靴加生命及少量攻击。
- 四品质N/R/SR/SSR，强化星数上限为1/3/4/5；每星在该装备基础属性上增加10%。
- SR/SSR生成时随机附魏蜀吴群阵营；匹配武将时该件装备属性乘1.3。
- 消耗其他装备和铜钱强化；单件/批量分解；装备加成已进入英雄面板与战斗输入。
- 战役首通有65%概率掉一件装备。当前挂机、重复战役、塔奖励与商店没有持续装备材料入口。

源码见 `utils/items.js`、`utils/store.js`、`src/screens/forge.js`、`src/screens/heroDetail.js`。本轮只读审计确认以下问题，不能将已有菜单视作系统已健全：

| 问题 | 玩家后果 | 建议 |
| --- | --- | --- |
| 装备成长依赖战役首通 | 卡关后装备侧无稳定解法 | 挂机持续产材料，里程碑与打造补缺件 |
| 强化按选中材料整批销毁，超过需求的点数不保留 | 选多了浪费；低级装备不敢强化 | 材料余额化、按实际需求扣除 |
| 被消耗的强化装备只按品质和星数折算少量点数 | 不能完整承接之前的投入 | 记录强化投入，重置/分解按账本返还 |
| 自动选料没有高品质/锁定保护 | 未穿戴的好装备可能被当材料吃掉 | 显式回收，默认保护紫橙与已强化装备 |
| 遣散英雄直接删除其装备 | 丢失玩家资产 | 先卸回背包；英雄专题若关闭本体遣散则同步覆盖 |
| `equipTo`未验证装备存在及槽位匹配 | 内核允许错误穿戴 | 核心接口校验，不能仅靠界面筛选 |
| `enhanceEquip`未去重材料ID | 同一件装备可被重复计点 | 拒绝重复ID或严格去重，整笔操作原子提交 |
| 超300件时自动删除部分白装，且数量算法不能可靠达成容量目标 | 玩家无回报丢装，背包也未可靠限额 | 首版取消静默删除，用可见回收和溢出暂存 |

上述异常由源码核对；其中错误槽位、重复ID、遣散删装、自动选料包含SSR经子agent独立内存态复现。没有访问设备存档。本轮未运行完整smoke/static-check，未做平台真机验证。

## 4. 装备构成：先让人看得懂

### 四个部位

| 部位 | 第一版主要属性 | 玩家怎么判断 |
| --- | --- | --- |
| 兵刃 | 攻击 | 输出不足；治疗按攻击计算的武将也可能需要 |
| 铠甲 | 生命 | 被秒、扛不住连续伤害 |
| 头盔 | 防御 | 经常承担可被防御减免的伤害 |
| 战靴 | 生命＋少量攻击 | 补充综合属性 |

沿用现有属性，战靴首版不增加速度、闪避。速度会改变行动和怒气循环，需在对战专题单独验证。所有职业可穿同槽装备，不加入重甲/皮甲/布甲限制，减少缺件组合。

装备名称采用“品质名称＋部位”，如百炼兵刃。军师拿兵刃代表攻击装备，不强制画成刀；未来可按职业改变展示名称，不改变实际物品和规则。独特历史名器留给未来专属内容，普通批量装备不都叫青龙偃月刀。

### 四档品质与一条强化线

| 品质 | 中文名 | 强化上限 | 定位 |
| --- | --- | --- | --- |
| 白 N | 凡铁 | 1星 | 新手补齐槽位、回收材料 |
| 蓝 R | 精钢 | 3星 | 前期主力 |
| 紫 SR | 百炼 | 4星 | 中期培养 |
| 橙 SSR | 神兵 | 5星 | 当前版本长线收集 |

装备SSR与英雄SSR是两个独立概念：白将也能穿橙装，SSR英雄不会自动获得SSR装备。

首版只有品质与强化星数两条可见信息，不同时增加装备等级。星数增强本件装备，不把蓝装变成紫装；要更高品质，通过掉落、自选或打造获得。暂沿用每星+10%的规则，现有跨品质基础属性跨度必须在数值阶段重新评估。

阵营先保留现有SR/SSR随机阵营、匹配+30%规则，明确只作用于本件装备提供的属性。例如兵刃原本+100攻击，匹配后+130，而不是英雄总攻击+30%。不匹配仍能使用；首版定向箱/打造可指定阵营，避免四槽×四阵营全部靠随机。不能因为设计变化删除旧档无阵营或提前获得的橙装。

## 5. 获得：好运能加速，差运气也有路

| 来源 | 主要产出 | 目的与边界 |
| --- | --- | --- |
| 新手与章节首通里程碑 | 固定部位装备、自选箱 | 教会穿戴并补齐空槽；领取标记持久化 |
| 战役首通普通掉落 | 随机部位装备 | 通过关卡的额外惊喜 |
| 挂机 | 精铁（通用装备材料）＋原有资源 | 卡关后仍有成长；沿用12小时累计上限 |
| 日常训练累计 | 定向装备箱进度 | 每次达成都会接近目标，不依赖连登，不因断一天清零 |
| 铁匠铺定向打造 | 选定品质、部位、适用时的阵营 | 用铜钱和精铁填补短板 |

“精铁”是现有强化点的可存储余额化，首版只加这一种装备材料，不为每个部位和品质再造一种货币。旧装回收、挂机、任务使用同一余额。

推荐章进度草案：第1章以白装和教学蓝装为主；第2–3章蓝装稳定产出；第4–6章开始紫装；第7章以后逐步开放橙装获取。这是新产出表建议，具体解锁关与概率要结合关卡难度确定，旧装备不回收。装备掉落概率与英雄招募无关，不修改英雄SSR2%与无保底规则。

定向箱绑定“获得时的奖励档位”，存着不开不会因后续推关自动升品质；兑换时选择部位和阵营。关闭选择窗口后箱子仍在背包；实际兑换成功才扣箱。日常累计建议每3次达标给一个当前已解锁品质的定向箱（以完成第3次时的进度固定奖励档位），是待验证起点，不能据此承诺橙装一定三天到手。

首版挂机只自动积累精铁，不自动创建大量随机装备，减轻背包和领取负担。精铁小数进度必须保留；多次领取不能比一次领取亏损或增加收益。跨章节调高产率前先结算旧产率时段，不追溯抬高已积累收益。新增装备产出不默认接入现有双倍广告或快速收获；基础免费预算独立成立，若后续纳入再明确倍率与上限。

定向打造不收费抽奖，预览即结果。配方消耗的精铁必须高于成品基础回收所得，铜钱不从成品基础回收中返还，杜绝打造—分解循环套利。强化返还另按实际强化账本计算，不含购买、打造、阵营调整等取得成本。

## 6. 强化与换装：让玩家敢培养

建议操作：装备强化只消耗铜钱＋精铁，成功率100%，不掉星。多余装备先回收成精铁；界面可提供选装回收并强化的快捷入口，但必须展示要销毁的物品和返还明细。

为每件装备记录累计强化消耗的精铁和铜钱。强化只扣到下一星所需的准确数量；材料不足整笔操作不变更。一键强化先预览可升星数与总价，不能顺手耗尽所有铜钱。

- **换人穿戴**：免费，原物品与强化一起转移，唯一归属；不复制装备。
- **卸下**：免费，物品回背包，强化不变。
- **重置强化**：装备保留为0星，返还账本中100%的强化精铁和铜钱。
- **分解**：装备本体消失，获得基础回收精铁，另返还100%已记录的强化投入。
- **培养转移**：同槽旧装重置，将返还资源用于新装强化，剩余留余额。预览新旧星数、返还与使用金额，默认不额外动用原有余额。两步作为一次事务执行。

无损的是投入价值，不是星数。蓝装3星花的材料转给紫装，不保证直接变紫装3星；系统必须解释目标星数及差额。新装已有强化时只补后续星级成本，不能重复退款或覆盖其账本。达到品质星上限后停止扣费。

完整例子：关羽穿蓝兵刃3星 → 获得蜀阵营紫兵刃 → 预览更换后攻击变化 → 选择转移培养 → 蓝兵刃变0星留背包，紫兵刃获得返还资源能够承担的强化 → 剩余铜钱/精铁留余额 → 蓝兵刃可给替补或回收。玩家知道每笔投入去哪了。

## 7. 一键配装与背包规则

英雄页显示四件装备、实际属性、匹配阵营标记与可提升提示。点击已穿装备进入详情，提供更换/卸下/强化，不以“点一下直接卸下”作为唯一入口。

第一版一键配装只使用该英雄当前装备与未穿戴装备：考虑品质、星数、实际阵营加成及该英雄职责；显示前后攻击/生命/防御差值。默认不抢其他英雄装备。玩家主动“从其他英雄调拨”时显示来源与受影响英雄，再整体转移。锁定表示禁止销毁，不妨碍穿戴；保护所有权的固定配装选项若以后需要应另命名。

全队分配在后续版本做：按前排生存、核心输出等玩家选定优先级分配，避免对英雄连续调用单人算法而重复推荐同一件装备。战力只是提示，不能把战力数值更高等同于适合所有战斗。

背包展示全部装备，能筛选“全部/未穿戴/已穿戴”、部位、品质、阵营、强化和锁定，并标出穿戴者。当前铁匠铺只列未穿戴装备，不利于集中管理。

保护规则：

1. 紫橙装备默认锁定；已强化装备默认不进入批量回收。
2. 锁定/已穿戴/目标装备绝不能被回收；禁止接口绕过。
3. 批量默认只选未强化、未锁定、未穿戴的白装；每个部位保留一件备用，名单可预览调整。
4. 回收高品质或已强化装备需主动解锁并显示损失/返还，不由一键选择代劳。
5. 取消当前超容量静默删除。首版以300件作整理提醒线，不强制删除；战利品若受实际技术容量限制，进入持久化待领取队列，不覆盖、不消失。队列与背包的容量/性能上限需压测后确定，不能写成无限库存保证。
6. 成功穿戴、强化、回收、开箱后立即保存；存储失败明确报错、保留可重试状态，不能提示永久保存成功。重复点击不得重复领箱或退款。

## 8. 与英雄、战斗的边界

英雄培养系统决定等级、星级、技能；装备系统决定额外属性与可转移资产；战斗读取开战时快照。英雄等级继承不复制装备，换人转装是独立且可预览的操作。无需等待英雄方案全部实施才能修装备安全和获取，但英雄删除/换将功能必须使用共同的装备归属规则。

基础结算建议：先算英雄等级/星级属性，再加每件已处理强化与阵营的装备属性，随后统一计算个人被动、套装（后续）、队伍光环和战中效果。每类百分比究竟加算还是乘算必须在对战规格里定义一次，英雄详情区分基础面板与入场加成，不能在面板和引擎重复叠加。

只增加一件生命装，不应意外改变攻击；同件装备匹配阵营只加一次；装备在战斗外转移不影响已开始的战斗。生命被动未生效、正常/跳过战斗不一致是已有评审指出的前置问题，不应靠装备加数值掩盖。

## 9. 数值预算与新手体验

先做可解释的目标，再跑模拟确定表。建议：第一章完成一次获得、穿戴、强化、换装，章末通过一次性奖励保证拥有五套基础四槽装备（20件，含此前固定教学装备；随机掉落另算）。当前只有四名初始英雄，第五套可留背包，不在装备任务里擅自改赠英雄规则；奖励不依赖随机抽到第五人。

教学顺序：第一件兵刃给主输出 → 一件铠甲给前排 → 赠一笔精铁强化一次 → 给更好同槽装备演示无损转移 → 解锁回收与定向补缺。重复进入不重发奖励；已有账号满足条件可一次性补领新里程碑权益，具体补领表单列。

建议前中期日常登录可完成若干次有感的强化，数日可定向补一件短板；这些是体验目标，不是已验证产率。日预算以不看广告、不付费、每日合理领取次数为前提，不能按24小时满在线计算。

数值工作必须交付：

- 分阶段五人队资源表：每日铜钱需同时支付英雄升级与装备强化，不能两套系统各自占满预算。
- 精铁净预算：日净积累=挂机＋任务＋回收－日常强化开销；打造耗时按净积累计算。净值≤0时须调整配方或独立给自选箱，不能宣称“攒几天就有”。
- 当前120关的20/40/80/120关检查点：合理英雄等级与装备条件下比较裸装/正常装/过量培养，观察伤害、生存、胜率和卡点；固定多个随机种子，不拿单场翻盘作结论。
- 可先以同阶段标准装备让裸英雄主要属性提高约20%–40%作为试算起点，不作为上线承诺；若压过英雄技能价值或后期几乎无效，应改表。现有白橙跨度与首关可随机出橙不直接照搬。
- 用坏运气路径验证：即使随机掉装没有升级，固定赠送＋日常箱＋挂机打造仍能接近下一目标；这与英雄招募无保底相互独立。

当前敌人有指数成长而装备只有固定品质与有限星数，不能宣称这一套可支持无限推关。先验收前120关；120关以后的无限模式需要单独确定敌我成长上限，再考虑橙装锻阶或其他长线内容。

## 10. 后续可增加的搭配玩法

基础循环验收后，第二阶段再做少量固定套装，建议三个方向：破军偏攻击、坚城偏生存、济世偏治疗。用“同套2件生效，4件加强或提供一个明确效果”的规则；一件只属于一个套装，穿四件时2件效果生效一次、4件效果再加一次；2＋2可激活两个2件效果。

套装效果先给方向不锁死百分比。通过定向打造/重铸选择，避免把品质×部位×阵营×套装再全部随机。旧装备可通过明确成本获得套装归属，保留品质、星数、阵营与投入。治疗、护盾等效果必须能在战报验证，套装不是仅面板加战力。

更后面才评估：橙装锻阶、少量核心武将专属装备。专武需改变玩法且可验证，独立预算与获取路径；不作为第一版推图必需品。宝石、洗练、随机副词条、多套装备页、PVP专用装备、装备付费抽奖暂缓。

## 11. 实施位置与迁移要求（尚未实施）

保持原生JS、无第三方运行时依赖。数值与配方放 `utils/items.js` / `utils/config.js`；纯规则可抽到 `utils/equipment.js`；`utils/store.js` 收口资产事务/存档；表现使用现有IMGUI，平台差异不进入装备模块。不改平台目录生成物，不移植legacy界面。

装备实例保留现有id/q/slot/stars/faction，新增锁定、强化精铁账本、强化铜钱账本；套装字段后续再加。资源新增精铁余额；存档增加装备箱、里程碑领取记录和必要待领取队列。可从英雄equip引用推导归属，避免又存一份owner后双方不一致。

迁移按实施时最新存档版本递增，不抢占其他会话已使用的版本号：

1. 备份旧状态，保留装备id、品质、星数、阵营与合法归属；缺字段给默认值。
2. 现有档没有强化投入账本，按旧版各星级必需点数和铜钱累计建立“可返还额度”。保留原星数，不同时直接发一笔退款；真正重置/销毁时才兑现并清零。
3. 该额度是明确迁移规则，不能声称恢复过去真实消耗；旧版超额喂入、被吃掉强化装和已销毁物品没有日志，无法精确追溯。不伪造资产历史。
4. 紫橙及已强化旧装默认保护；旧版无阵营装备继续有效，不随机改其阵营。
5. 发现重复引用、错误槽位或孤立引用时，保留实际物品，撤下非法引用到背包；记录修复，不复制物品也不直接删物品。
6. 重复迁移结果不变，无重复退款或补领奖励。新账号与旧账号使用同一套核心逻辑。

所有消耗操作先完整校验物品、归属、锁定、余额、合法枚举、整数非负数量与重复ID，再一次提交；任何失败资源与装备都不变。测试使用临时内存存储桩，禁止读取或修改真机存档。

## 12. 分期与验收

| 阶段 | 必做交付 | 退出条件 |
| --- | --- | --- |
| P0 资产可信 | 槽位/ID/锁定校验、材料去重、遣散归还、去静默删除、操作保存 | 不丢装、不复制、不绕过保护；失败零变更 |
| P1 可持续可玩 | 精铁余额、确定强化、退款/转移、挂机产出、新手补装、自选箱/定向打造、前后属性比较、一键配装、旧档迁移 | 完整走通获得→使用→替换→回收；卡关仍可成长 |
| P2 有搭配深度 | 三类固定套装、确定选择、全队配装与战报反馈 | 同等级同品质下不同配置能解决可解释的战斗问题 |
| P3 长线扩展 | 根据前120关数据决定锻阶/专武 | 有独立成长预算与获取路线，不覆盖基础系统缺陷 |

P0＋P1共同构成第一版完整装备系统，不能只修按钮就称完成。P1内部先做交易/迁移，再做稳定产出与教学，最后平衡验证；主程统一收口store/config等热点文件。

必须覆盖的验收场景：

- 武器不能装进铠甲槽；不存在的装备、英雄、非法星数等安全拒绝。
- 同一件装备只能由一个英雄一个槽持有；转移后原拥有者正确卸下。
- 材料ID重复不能变出强化点；批量回收不能吃掉锁定/穿戴装备。
- 重置返还累计投入且清零账本，重置两次不多退；分解返还账本＋基础材料，不返取得成本。
- 转移投入前后余额与投入守恒，不复制星数；材料不足/取消时状态不变。
- 打造再分解不产生资源净收益；关闭自选框和重启不会吞掉自选箱。
- 一键配装不抢其他武将装备；阵营加成只作用于本件装备且只算一次。
- 多次小额挂机领取和一次累计领取总产出一致（扣除明确上限）；掉线/跨日/进度变化不重复发奖。
- 新手五套基础装备可确定获得；卡在同一关仍有精铁与累计自选进度。
- 背包超过提醒线不静默删装；溢出领取不丢失、不中途重复入账。
- 旧档装备守恒、合法战力不因字段迁移下降，退款与补领只能兑现一次。
- build同步、smoke、static-check通过；UI变更补离屏逐屏审查并在双平台工具验证关键路径。测试通过和用户验收分别记录。

建议先讨论三个产品选择：保留个人四槽＋免费转移；强化投入100%可返还；随机掉落之外提供常驻定向获取。本文推荐全部采用。套装和专武后置，具体产率与费用在实施时先交数值表和模拟结果再验收。
