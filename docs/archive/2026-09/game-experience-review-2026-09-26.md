# 《挂机定三国》多维体验评审与整改方案

日期：2026-09-26；评审：Codex；代码基线：`bd5ad5d`。本文为评审与方案交付，**没有实施游戏修改，没有形成新的产品决定**。

## 1. 判断与范围

**现在是一款系统骨架较齐全、内容量增长很快，但体验成熟度明显落后的可玩原型。** 最大问题是玩家很难认出武将、看懂战斗、理解下一步培养目标；同时存在输入与资产结算错误，削弱规则可信度。继续扩将、扩玩法、堆特效之前，应先让现有流程可靠，再做一章能够体现品质的完整体验。

评审依据：共享交接与当前源码；原源码在临时浏览器 Canvas 容器中的实际画面（独立内存存档）；纯 Node 输入/战斗/养成复现；现有测试。没有访问用户真机存档，没有进行微信或抖音真机性能、留存、付费或广告收益测试。下文用户反应属于设计判断，不是假称已获得用户访谈数据。

主观评分以“面向陌生玩家的小规模体验测试版本”为标尺，不是行业排名：

| 维度 | 评分 / 10 | 判断 |
| --- | ---: | --- |
| UI 与美术 | 4 | 黑金方向统一，但几乎全是面板、字牌、Emoji；内容堆在上方，视觉主角缺失 |
| 交互 | 3 | 功能能找到，但热区过小、滚动命中错位、排序超屏、弹层层级有问题 |
| 剧情 | 4 | 120关有文字，但敌方身份、事件时序、胜利目标与故事脱节 |
| 战斗 | 4 | 有站位、回能、克制、状态骨架；播放一致性、效果语义与复盘不足 |
| 特效与声音 | 2 | 主要是飘字、发光框和横幅，攻击关系弱；共享源码未接入音效/震动 |
| 养成与经济 | 4 | 共鸣、装备、升阶齐备，但资产处理有漏洞，培养路径与价格体系不清晰 |

值得保留：内核/表现分离、双平台适配边界、可播种战斗与事件流、共鸣水镜、装备阵营加成、剧情纯数据表。无需推倒重做。

## 2. P0：先修“玩家是否能相信这个游戏”

以下不是审美偏好。优先级含义：P0阻止扩大测试，P1构成第一版完整体验，P2在样板验收后扩展。

| 编号 | 问题与证据 | 解决方案 | 验收标准 |
| --- | --- | --- | --- |

| F11 | 广告复活以己方30%血重新建战斗，敌人也满血；免费再战则己方满血。场景第63/295行 | 保留敌方战局状态后复活我方；或改名为带明确增益的重战。先确定一种语义再实现 | 广告奖励有明确正收益；未完整观看不发奖；每局次数与重复结算可控 |

输入层还要一并整理：`ui.hitAt`跳过无回调遮罩，不能靠空回调阻挡底层；`app.frame`在场景弹窗后绘制并注册底部导航，弹层无法天然阻挡导航；底层dragAreas也未由弹窗隔离。解决方式是统一模态输入层：先阻止下层命中/拖拽，再绘制窗口与内部控件，不让各场景各写一套遮罩。

当前战役的“战败推关/奖励不入账”已在此前修复；F03指仍有问题的**塔分支**，不应把旧问题重复报为未修。

## 3. UI：有主题色，但缺少真正的视觉主体

### 锐评

第一眼像一套套了三国配色的数值管理面板。姓氏牌适合作占位图，却承担了120武将的全部身份；张飞、张辽、张郃首先都是一个“张”。黑金不是问题，所有元素都以同样强度使用黑金才是问题。

实际观察与源码相符：

- 主城主要内容到约452逻辑像素就结束，812高屏幕中间大片空置；上面却挤着战力、资源、广告、入口、阵容。留白没有服务于场景、主将或章节氛围。
- 群英排序从x=248开始，四个控件最右到468，画布宽375：品质部分超屏、品阶完全超屏。`src/screens/heroes.js:50–61`。
- 群英卡头像高约104，姓名放在卡内y+74，标题y+90，文字叠在头像下部。当前是字牌都拥挤，换真立绘后会更严重。
- 铁匠按钮高17、筛选20、主城出征26逻辑像素；大量功能文字9–11px。不是“古风就该小字”，是信息层级没分开。
- 通用字体全部走楷体/宋体回退；细小数字、长说明同样使用装饰字体。资源/武器图标用Emoji，实际画面有字形缺失和风格混杂。
- 顶栏与底栏直接贴屏幕边缘，当前未见安全区/胶囊避让。真实双平台设备需要专项验证，不能从桌面截图宣称适配完毕。

### 方案

1. **先定组件规格。** 375逻辑宽为基准，边距12–16，8为常用间距；正文建议14–16、辅助12–13、标题20–24，数值使用清晰系统字体，楷体只保留在标题/章节。主操作视觉高度44左右，重要控件热区至少44×44逻辑像素；这是项目建议目标，不是外部规范引用。
2. **颜色承担明确意义。** 金色用于奖励/当前主操作，朱砂用于出征/危险；普通容器减弱双描边；稀有度色与阵营标记分工，不能让一个彩框同时解释两个概念。
3. **主城重排为三段。** 顶部精简资源；中部章节场景+事件名+敌方特点+一个出征主按钮；底部挂机收获与阵容快捷入口。任务、塔、演武不全部抢首屏。保留王庭聚合，但说明入口是“玩法”，文案不要把“玩法闭环”这种策划用语直接给玩家看。
4. **群英页两行工具栏。** 第一行阵营筛选，第二行排序下拉+职业筛选；姓名、稀有度、等级在肖像区之外；成长提示最多一种，减少卡片上的无效信息。
5. **详情页围绕决策。** 顶部主将肖像和职责一句话；中部技能要点与状态标签；底部固定升级/装备主操作。基础属性可展开。遣散移到更多菜单，和常用升级拉开空间。
6. **美术先交付核心阵容。** 先做8–12名核心武将的头像、卡面、战斗小像与统一身份特征，再扩到120将。每人固定武器、轮廓、主辅色、饰物；共享同一设定而非每种尺寸重新设计。其余武将继续兜底，避免半成品阻塞游戏。
7. **场景先做3套可复用底图。** 营寨、关隘、江岸；章节通过旗帜、时间、火势和远景变化建立辨识。素材加载失败保留程序化背景；资源尺寸/格式/分包方案由实机内存、包体测量后决定。

验收：主城3秒内能找到出征与收益；卡片姓名不压肖像；320/375/430宽逻辑适配与短/长屏均可操作；关键图标不依赖Emoji显示；主操作在安全区内。

## 4. 交互：让一次操作有结果、有反馈、可恢复

### 锐评

目前“按钮很多”却不等于“操作顺”。例如换装备要先点已穿装备卸下，再点空位选新装，没有比较；升阶直接消耗资源，却缺乏明确材料预览；结果弹层能被导航打断；短屏十连的确认按钮位于y=621–653，667高屏的底栏从615开始，直接覆盖。

### 方案

| 流程 | 推荐交互 | 必须处理的边界 |
| --- | --- | --- |
| 换装备 | 点槽位直接打开“当前/候选”比较，显示攻/血/防净变化与阵营匹配；确认替换 | 不把已穿装备自动当材料；切后台恢复选择状态或安全取消 |
| 编队 | 点槽位换人，已上阵角色允许交换；候选显示职责与阵营加成变化 | 首版点击交换足够，拖拽以后再做；一键布阵标为战力推荐，避免承诺最优 |
| 升阶/强化 | 展示将消耗的具体卡/装备与溢出点数；锁定物品默认排除 | 稀有卡、培养过装备不可被无提示自动选入 |
| 重置/遣散 | 先展示返还/损失明细，危险动作有独立确认 | 先修实际装备返还；核心重置限制与返还比例需重新评估，不能伪装为bug直接改数值 |
| 十连结果 | 布局按可用高度计算，卡区可滚动，确认区固定；提供跳过演出 | 模态状态阻挡底栏；继续招募时明确本次成本 |
| 战败 | 再战、调整阵容、培养入口；给事实性失败线索 | 保留关卡上下文；不能只有“已至尽头”这种与败因无关的禁用文案 |

补齐统一反馈：按下即时反馈；操作成功短提示并更新数字；资源不足给缺多少与获取入口；失败可恢复。关键交易完成后立即保存，10秒心跳与切后台保存继续作兜底。

验证不只截图：对群英、铁匠、装备选择、自选卡、编队选择逐个执行“滚动→点击→核对对象”；模态打开时底层按钮/滚动/导航均不响应；连续点击不重复扣除。

## 5. 剧情：让三国事件改变你怎样打

### 锐评

现在是给同一种五人战斗加了120段不同字幕。第一关说打黄巾，守军却是纪灵、袁术、公孙瓒、于吉、杨修；主城会直接显示这些名字。这个违和感靠“不在旁白点名”藏不住。

“温酒斩华雄”战前旁白已经写华雄首级扔到帐前，接下来玩家才开始打；“三顾茅庐”“白帝托孤”也硬配五人敌阵。第九/十章局部事件顺序回跳且未标为回忆。问题不是字少，而是文字、战场与胜负没有互相支撑。

证据：`utils/story.js:14–19,49–50,141–144,281–288,312–319`。主城已有章节却未展示每关事件名：`src/screens/home.js:23–30,68–69`。

### 方案

- **先把第一章做成样板。** 章首交代行动目标，普通关一行情报，两次局势变化，章末一个机制Boss；不要10关全放长对话。
- **独立NPC身份。** 黄巾刀兵、力士、术士有自己的名字和外观，能力可以复用模板；不必为了路人敌军扩抽卡池。
- **拆分战前与战后文本。** 战前“华雄在关前搦战”，胜后才写“温酒尚热”；败北不出现已获胜的故事结论。
- **增加极少量关卡目标。** 先歼灭、坚守、护送/保护、斩首四类定义；胜负必须由内核裁定，UI只呈现目标与进度。
- **故事人物与自由阵容分离。** 不要求玩家抽到诸葛亮才能经历三顾茅庐；必要时提供仅该关可用的剧情援军。
- **允许非战斗节点。** 三顾可以是行军剧情/招贤教学；并非每个名场面都需要把五个人打趴。
- **可跳过、可回看。** 增演义录入口；跳过只记播放状态，不剥夺后续回看。普通关重复挑战不重复打断。

样例提案（均未实施）：

| 事件 | 胜利目标 | 关卡机制 | 玩家学到什么 |
| --- | --- | --- | --- |
| 广宗破阵 | 击败主将 | 术士在场时为前排维持护盾，术士位置/技能预先可见 | 后排点杀优于只堆总战力 |
| 长坂护送 | 坚守到撤离完成 | 护送对象受到压力，玩家需保护与治疗；计时条清晰 | 坦克/治疗职责与输出同样有价值 |
| 赤壁破船 | 击败指挥舰 | 火势节点可被利用或打断，敌我效果明确 | 技能配合而非只有倍率 |
| 麦城突围 | 达成撤离条件 | 成功撤离即可过关，战场表现与叙事基调一致 | “过关”不必改写成全歼敌军 |

验收：试玩者能说出本关为何开战、怎样获胜、至少一处与上一关的差异；敌人身份不自相矛盾；无未标注时间回跳；不看剧情也能从目标UI理解规则。

## 6. 战斗：从“结算器”变成“能看懂的交锋”

### 锐评

不能说完全没策略：已经有前后排、阵营克制、同阵营加成、射手目标选择、能量、控制、持续伤害。但玩家主要看到姓氏牌减血，很难知道是谁打谁、谁救了谁、为什么输了。

120将中95将的被动主要是自身常量属性、治疗增幅或减伤等修正；28将大招只有一个伤害效果指令（可为多段/多目标，不能误说全部单体）。名字丰富，决策差异相对不足。

### 方案

1. **先统一规则。** 修复F01–F04；一次技能默认锁定目标，后续效果复用同一目标集，独立重新选目标必须显式声明；明确同源刷新、异源叠加/择高；区分防御增加与直接减伤。限时未击败敌方判攻方失败，应在战前说明。
2. **战前可读。** 敌方显示职责、危险技能、主要目标；己方显示缺前排/缺恢复等建议及依据；不把纯战力高低当必胜结论。
3. **战中可追踪。** 普攻有施法者→目标的动作/弹道，血条在命中时反馈；控制/护盾/灼烧有明确标志。手动开大不是当前第一优先，先把自动战斗的因果做清楚。
4. **战后可解释。** 输出、承伤、有效治疗、关键控制、首个阵亡时间；内核已有部分统计，但治疗目前记在被治疗者，DOT/反伤归因也需修正。先修统计再做榜单。
5. **先做4种可用打法。** 保护反击、后排点杀、火攻联动、控制回能。用首发8–12将组成可读配合，建立关卡克制，而不是继续给每人加5%属性。
6. **三种模式各有目的。** 战役教机制并承载故事；塔考验阵容应变并给里程碑；演武目前是种子NPC挑战，不应包装成已实现真实玩家异步竞技。先完善NPC挑战，联网对战另立项目。

规则待明确项：前排全灭后`frontRow`技能是否转后排；增减益覆盖规则；复活是否继承敌方剩余状态。把它们写成明确设计后做测试，不能让实现偶然决定规则。

验收：同等养成的两种站位/职责替换能在设计的教学关产生可解释差异；玩家能根据战报提出一次合理调整；正常/加速/跳过结果一致；面板技能描述与实装一致。

## 7. 特效与声音：先补“打中”，再补“华丽”

### 锐评

当前不是完全没特效，但有效信息不足。普攻事件发`uid`，画面却读`ev.src`，连已有跳动都没真正触发（`utils/battle.js:272`、`src/screens/battle.js:136`）。多数大招共用边框发光+名字横幅，群攻再加金闪；关羽斩击和军师阵法缺少形态差异。多个大招覆盖同一个横幅，伤害/治疗/护盾在同点飘字。

### 最小效果体系

以下时间是拟定设计预算，需在修复真实战斗时钟后试调；不修改模拟时间、不靠演出改变胜负。

| 层级 | 实现 | 拟定时长/限制 |
| --- | --- | --- |
| 按钮 | 亮度/缩放微反馈+轻点击声 | 80–120ms；立即响应 |
| 普攻 | 近战前冲挥击、弓箭轨迹、法术弹；命中白闪/小位移 | 250–400ms一个动作；命中时间明确 |
| 暴击 | 强化命中特效与独立音色，数字更突出 | 不为每次暴击全屏震动 |
| 治疗/护盾 | 绿粒上升、蓝色轮廓；护盾破裂反馈 | 不遮血量和怒气条 |
| 控制 | 头顶图标+持续信息，状态结束明确消失 | 区分沉默与眩晕 |
| 核心大招 | 短前摇→轨迹/范围→命中→收束 | 约0.7–1.2秒；2倍速压缩装饰，不丢关键提示 |
| 结算 | 胜败差异、奖励逐项入账反馈 | 可立即继续，不强迫等完整演出 |

先做六类可复用效果：斩击、穿刺、范围阵纹、治疗、护盾、控制。再给核心武将加标识：关羽定向青龙弧、张飞扩散冲击、诸葛亮地面阵纹、周瑜连片火势、赵云穿刺轨迹、刘备援护光效。每个效果既传达人物，又传达作用。

飘字按目标排队：同类80–120ms内合并，最多2–3条错位，暴击/免死优先，持续伤害降权。横幅用队列/并发摘要，不覆盖重要技能；满屏同时施法时限制装饰粒子，保留命中/状态/血条。

新增表现模块可考虑`src/fx.js`与`src/audio.js`，事件订阅留在表现层；平台音频/震动能力仍经`utils/platform.js`适配；规则数值与效果参数分别集中管理。首版音频用点按、三种攻击、命中、治疗、控制、大招、胜败；不必立即做全员配音。

音量、震动、低特效可独立关闭。缓存静态底图/头像，限制粒子对象与重复渐变；在指定低端真机测P95帧耗时、峰值内存、卡顿和音频并发，目标可先定稳定30 FPS、较高设备60 FPS。**本轮没有实机性能结果，不能声称达到这些目标。**

## 8. 抽卡与养成：让抽到的人有用，让想养的人有路可走

### 锐评

初始给刘关张三个SSR，让玩家的品质参照从最高档开始；后续大量低稀有度新将容易被当作材料。120将池又让特定核心的重复卡更难获得，而升阶从第一星就需要同名卡。

依据现有固定SSR 2%、16名SSR等概率：

| 情况 | 数学结果 |
| --- | ---: |
| 12抽没有SSR | `0.98^12`≈78.47% |
| 50抽没有SSR | ≈36.42% |
| 100抽没有SSR | ≈13.26% |
| 单抽获得某一指定SSR | 0.125% |
| 仅靠随机池等到该指定SSR | 期望800抽，非保底、非承诺 |

用户已明确固定概率、无保底。本方案保留这一决定，不擅自加入软保底/十连保底/心愿加权。

### 方案

- 详情展示“下一步成长”：等级/星级目标、同名卡与兵魂缺口、可前往入口；让玩家知道要做什么。
- 展示现有500碎片SSR自选的确定性路径，可标记目标武将；先修F06/F07，兑换路径才可信。
- 共鸣水镜已实现，应该教会使用：第五名培养者是谁、为什么共享等级还低、新将自动共鸣到几级。不能把“没有共鸣”当缺陷。
- 新将出现时提示职责、当前可用位置、已有共鸣等级；让低稀有度也能在特定教学关有作用。是否做额外收藏属性/兑换资源，是后续数值决定。
- 抽卡演出三步：招将信物聚光→稀有度信号→人物揭示。普通结果快速，首次SSR有独立展示；十连可跳，结束能看清新增/重复/下一步用途。先有可辨认的人物，再拉长揭示才有意义。
- 核心前五禁止重置、其他重置返70%的组合会增加换将试错成本；应设计安全的核心更换/培养迁移方案。比例与限制变更单独拍板，现阶段先把限制解释清楚。

验收：新玩家5分钟内能填满五人、理解一次前后排调整；能找到一个指定SSR的非随机获取路径；换将后清楚等级从哪来；十连无需等长动画、确认不会被遮挡。

## 9. 经济与长期内容：先证明这120关能合理玩到

当前初始50元宝快收给3600铜钱+2400兵书；集市80元宝能买20万铜钱，或15万兵书。单以铜钱/元宝比较，集市约为快收34.7倍；这个比较未计快收同时给的兵书，但足以说明价格标尺不一致。

敌方等级线性上涨，还叠加`1.05^(关卡-1)`属性倍率：30/60/120关额外倍率约4.12/17.79/332.30，Boss另×1.25；我方等级200封顶。此为结构性风险，**没有完整扫描前，不能断言所有阵容无法通关120关**。

方案：

1. 定义资源价值标尺：按进度折算“若干小时资源”；奖励、商店、快收、广告用同一预算表，礼包折扣明确呈现。
2. 做三条首日预算：不看广告、有限广告、使用初始元宝。列出5人升10/20级、首次升阶、关键装备所需资源与预计等待。
3. 通关扫描分首发阵容、合理成长阵容、满养成上限阵容，多seed检查章首、章末与中后期；记录胜率、时间、卡点来源。
4. 再调分段难度。小关用于验证成长，机制关考布阵，Boss形成章末峰值；新章避免毫无解释的断崖。
5. 主城回流提供“离线得了什么—这次能提升谁—提升后挑战哪一关”三步。每日任务优先奖励正常游玩，不用额外操作来回领取填满屏幕。
6. 游戏存档与广告已具备基础，但目前无留存数据；先观测首战完成、首次换将、第5/10关、首次卡点和次日回访，再判断内容是否留得住人。
