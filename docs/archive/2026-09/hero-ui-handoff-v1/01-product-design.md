# 群英录与关羽详情：产品需求与视觉规格 v1

日期：2026-09-27。交付状态：设计与开发交接规格；不代表 Cocos 已实现、素材已通过实机验收或产品已发布。

用户已选定上一轮两张图的界面方向。本稿以 [群英录样稿](../prototypes/heroes-v1/hero-roster-v1.png) 和 [关羽详情样稿](../prototypes/heroes-v1/hero-detail-guanyu-v1.png) 为视觉基准，将画面拆成可以落地的动态组件。图片中的 Lv.40、27/120、3 星、资源余额、属性以及出战名单均为演示，不能写成初始化数据。

## 1. 目标、范围与优先级

玩家应能在群英录中识别自己有哪些武将、哪些已上阵，按阵营和养成结果找到目标，进入关羽详情理解技能与成长，再主动进入编队或共享军械。视觉主角是立绘，功能主角是“理解武将并调整阵容”。

| 编号 | 优先级 | 需求与边界 |
|---|---|---|
| PR-01 | P0 | 以三列立绘卡片构成英雄列表；真实持有数据、阵营筛选、战力/品质/星级排序、连续滚动、详情返回恢复位置。 |
| PR-02 | P0 | 关羽作为首个完整示例：同一角色设计用于列表裁切与详情大立绘；其余角色未具备素材时使用可辨别的姓名占位，不能把关羽换名复用。 |
| PR-03 | P0 | 详情包含身份、品质、星级、共享等级、上阵状态、属性、现有两个技能、共享军械入口、自动升星说明、调整编队。 |
| PR-04 | P0 | 延续统一等级、重复同名卡自动升星、全军共享军械；本轮不增加数值、卡池、货币、个人升级或个人装备。 |
| PR-05 | P0 | 保留现有首胜选择、多余同名卡保护/兑换、自选券等条件能力，通过次级区域承载；不因重做页面使旧能力不可到达。 |
| PR-06 | P0 | 可点击区域在375宽逻辑坐标下至少44×44；真机安全区、刘海/胶囊避让、短屏滚动、文字清晰。 |
| PR-07 | P0 | 原画与装饰可用图片；中文、数值、星级、筛选选中态、按钮状态均由 Cocos 节点生成。禁止以整屏截图承载实际交互。 |
| PR-08 | P1 | 列表复用/按需加载、图片加载失败兜底、按钮防重复提交与过渡动画；不以反复整屏重建实现每帧刷新。 |

本交付覆盖两个页面及必要弹层和跳转契约，不重新设计召唤、编队、军械和战斗的完整业务。新开发应接入根目录 Cocos 工程；旧 `src/` 用作规则和行为对照，不新增 Canvas 兼容壳。

## 2. 规则真值与关羽内容

### 2.1 数据必须来自现有内核

以下是阅读仓库时核对到的接口，生产代码在 Cocos 中使用同步生成的 `assets/scripts/domain/` 镜像；规则源仍为 `utils/`。新增 UI 不能手改生成镜像。

| UI 数据 | 规则/接口来源 | 展示约定 |
|---|---|---|
| 武将身份、称号、阵营、职业、品质、技能 | `heroes.getHero(id)`；`config.FACTIONS / CLASSES / RARITIES` | 名称来自配置；不要沿用当前页面手写的“战士/坦克/法师”映射替换配置中的“武将/猛将/军师”。 |
| 全体等级 | `store.playerLevel()` / `getState().player` | 主公等级只展示一次；卡片不重复展示相同等级。 |
| 已拥有列表、个人战力 | `store.allRoster()` / `store.calcHero(id)` | `calcHero` 先验证 `getOwned(id)` 与 `getHero(id)` 存在；现函数直接读取持有对象，不支持未拥有 ID。 |
| 星级、额外卡、保护状态 | `store.getOwned(id)` | 读取 `star/cards/lockedCards`；不能从图片上的星数反推真实数据。 |
| 上阵 | `getState().formation.includes(id)` | 只显示已上阵与所在槽位；卡片上不提供直接下阵。 |
| 属性/共享军械加成 | `calcHero(id).stats` / `getArmoryBonuses()` | 展示内核当前面板值，不再次在 UI 叠加被动、军械、阵营加成。阵营/战斗内加成与面板口径不可混称。 |
| 总收集数 | 有效持有 ID 数 / `heroes.HEROES.length` | “已拥有 N / M”不随筛选缩小；筛选结果另写“当前 X 名”。 |
| 首胜选择 | `store.firstWinChoice()` / `claimFirstWinChoice(id)` | 仅满足现有条件才出现入口；奖励到账才刷新。 |
| 编队提交 | `store.applyFormation(ids)` | 完整5槽阵容事务返回成功后刷新；页面不直接改存档数组。 |

品质与星级是两个维度。品质文字固定为 N/R/SR/SSR，品质边框色读取配置；星级上限读取对应 `RARITIES[rarity].maxStar`：

| 品质 | 框色基准 | 星级范围 |
|---|---|---|
| N | `#C8CCD4` 银白 | 0～2 |
| R | `#6F9FD8` 蓝 | 0～3 |
| SR | `#B07FE0` 紫 | 0～4 |
| SSR | `#F0A83E` 橙金 | 0～5 |

首次获得为0星；重复获得同名武将且未满星时自动升1星，满星后的卡保留。页面没有“升星”付费按钮，不显示不存在的升星铜钱或材料进度条。满星、保留卡、保护和兑换根据真实状态展示；数字化规则变更应回到内核另立需求。

## 3. 视觉语言与素材分层

采用样稿的墨绿漆木、铜金细边、浅绢纸字色与水墨城关。关羽为深绿头巾、长黑髯、铜金甲、青绿袍、偃月刀的成熟武将；列表与详情必须保留相同脸型、头巾、肩甲轮廓和衣纹系统。大背景低对比，角色脸部和轮廓高对比，界面装饰不得抢过角色。

| 令牌 | 建议值 | 使用 |
|---|---|---|
| 漆木深底 | `#102824` | 页面及底栏 |
| 深墨遮罩 | `#0A1716` | 信息背板、立绘下沿渐变 |
| 深青主按钮 | `#24634F` | 调整编队主行动 |
| 铜金边 | `#B99752` | 面板、选中态轮廓 |
| 暖金强调 | `#E4C783` | 标题、选中图标 |
| 绢纸正文 | `#F1E4C5` | 姓名、主要文字 |
| 次级文字 | `#C0BAA7` | 说明、非主要标签 |
| 朱砂标记 | `#8A4233` | “出战”角旗，必须带文字 |

以上为 UI 装饰建议，不覆盖 `config` 的阵营/品质语义色。阵营同时用徽章轮廓、魏/蜀/吴/群文字与颜色表示；选中态同时用描边与勾/亮底，不依赖单一颜色。品质框、阵营章分别独立，不能把“绿色蜀章”误当绿色品质。

资源分层：城关背景独立一层；人物透明立绘一层；卡框/按钮边/纹样一层；小图标一层；文字/数值为节点。装饰素材不带动态中文、稀有度字母、星级、选中描边或资源金额。资源编号、透明通道和拆图清单以本交接包资源清单为准；此文规定用途，不声称所有资源已导入游戏或全部通过验收。

### 字体与字号

设计坐标采用 **750×1334**，相当于375宽的2倍尺寸。标题可用经确认许可的中文宋体/书法感字体；正文用清楚的中文黑体。建议先以系统中文黑体实现可运行版本；评估思源黑体/思源宋体等字体包时必须核对实际下载包的许可与分发条款，随项目保存许可文件。不得从样稿抠出汉字拼成字库；不能假定本机字体可随游戏分发。

| 类型 | 750坐标字号/行高 | 对应375宽逻辑字号 | 约束 |
|---|---|---|---|
| 页标题 | 46/56 | 23 | 书法感只用于短标题 |
| 关羽大名 | 64/72 | 32 | 2字，不遮挡面部 |
| 武将卡名 | 30/38 | 15 | 最长姓名在卡内一行完整展示；不足空间降低到28，不截断成同名 |
| 技能/主按钮 | 30/40 | 15 | 中文“青龙偃月斩”允许两行 |
| 正文/金额/属性 | 28/40 | 14 | 必须可读，不以装饰字体承载长说明 |
| 次要标签 | 24/34 | 12 | 品质、阵营、辅助说明的下限；不得靠整屏缩放变得更小 |

## 4. 群英录：结构、尺寸与行为

以下坐标原点为**安全区内容左上角**，基准示意暂按可用区750×1334。真实设备先扣除平台安全区/顶部胶囊占用，再布局；不能把这些示意坐标当作全机型绝对值。横向边距24，网格间距12。

| 区块 | 基准区域 x/y/w/h | 构成与行为 |
|---|---|---|
| 顶部画卷 | `0 / 0 / 750 / 176` | 左侧群英录标题和城关背景；右上铜钱/元宝只读，右下调整编队按钮至少200×88。资源图标40×40，金额独立 Label。无实际充值功能，不保留样稿中的假“+”按钮。 |
| 共享等级条 | `24 / 176 / 702 / 68` | “主公 Lv.{level} · 全体武将共享等级”；收集数按空间放右侧或第二行。 |
| 阵营筛选 | `24 / 244 / 702 / 100` | 全部/魏/蜀/吴/群，各热区≥88×88，均分；视觉圆章可64×64，文字在章内或下沿，不缩小触摸区。 |
| 排序条 | `24 / 344 / 702 / 88` | 战力/品质/星级三等分按钮，默认战力降序，右端可显示下箭头；仅三种排序，不展示无意义的共享等级排序。 |
| 卡片滚动窗 | `24 / 432 / 702 / 744` | 三列；宽226，列间距12；卡片高度300，行距16。内容实际行数由筛选结果决定。 |
| 规则提示 | `24 / 1176 / 702 / 48` | “重复获得同名武将，自动升星”；不接受点击，不伪装按钮。 |
| 全局底栏 | `0 / 1224 / 750 / 110` | 主城/玩法/战役/英雄/背包，5等分，每栏150×110，英雄选中；图标48～56，标签26。 |

**原图的一行阵营+排序需拆为两行。** 五阵营加三排序在375宽的一行无法同时保证清楚文字和44逻辑像素触摸区。保持原图视觉语言与卡片主导，调整可操作的布局。**不要求第一屏同时显示九张完整卡片**：此基准显示两行完整卡片和第三行一部分，以提示可滚动。

### 4.1 HeroCard 规格

卡片原点为自身左上角，226×300，整个矩形为进入详情的热区。所有角标仅展示，不设置与卡片冲突的独立小热区。

| 部件 | 卡内位置/尺寸 | 说明 |
|---|---|---|
| 角色图窗 | `4 / 4 / 218 / 292` | 同一透明立绘以裁切数据形成半身图；卡片 Mask 裁切，不能拉伸人物。 |
| 阵营章 | `10 / 10 / 52 / 52` | 章底+独立文字；五官主体预留在右侧或中间。 |
| 品质字 | `154 / 12 / 62 / 38` | N/R/SR/SSR可读，独立于边框图。 |
| 出战角旗 | `10 / 66 / 48 / 70` | 仅在阵容中出现，“出战”两字；不能靠红色旗代替状态文字。 |
| 底部渐变 | `4 / 210 / 218 / 86` | 保证卡名和星级对比，不盖脸。 |
| 姓名 | `10 / 222 / 206 / 38` | 居中或对齐统一，不按不同英雄自由漂移。 |
| 星级 | `10 / 262 / 206 / 30` | 实心当前星、暗色空星至本品质上限；0星仍可见空星。SSR最多5，N只能2。 |

主图窗保留甲片/武器作为身份线索，禁止只裁成大头照。占位图用阵营低对比底+姓名/字形，不显示随机他人肖像。战力是排序依据，列表上不强行叠加更多小字；需要比较时可在详情看数值。屏幕阅读/辅助描述应串联姓名、阵营、品质、当前星级/上限、已上阵状态。

### 4.2 筛选、排序与返回状态

| 编号 | 行为 |
|---|---|
| LI-01 | 默认全部阵营+战力降序，只展示已拥有的有效英雄。未拥有图鉴不是本轮新增功能。 |
| LI-02 | 筛选使用阵营 key 精确匹配，切换阵营或排序回到列表顶部；重复点当前选项不重置滚动、不反转升降序。 |
| LI-03 | 战力排序为 `(power DESC, rarity DESC, star DESC, id ASC)`；品质为 `(rarity DESC, star DESC, power DESC, id ASC)`；星级为 `(star DESC, rarity DESC, power DESC, id ASC)`。`id ASC`按稳定字符串顺序，不依赖中文 locale，也不把多字段乘常数相加。 |
| LI-04 | 排序使用未格式化整数/数值，不能用“12.8万”字符串排序。排序过程中不直接修改 store 返回的原始持有顺序；先构建UI数组。 |
| LI-05 | 进入详情保存 `{faction, sort, scrollOffset, anchorHeroId, anchorLocalY}`；返回先还原筛选排序、刷新真实数据，再以锚定卡片恢复位置，锚点消失则夹紧旧偏移到有效区间。 |
| LI-06 | 详情/军械/编队返回列表保留状态；从其他全局标签回来也保留本次会话列表状态；冷启动回到默认。无需为UI滚动修改玩家存档结构。 |
| LI-07 | 背景自动战斗使等级/战力变化时更新可见值，但手指拖动/惯性滑动期间不重排；滚动停止后或页面再进入时重算，并保留锚点，避免玩家误点移动目标。 |
| LI-08 | 列表滚动手势不得触发卡片打开。阵营/排序/底栏固定，手势仅作用于列表；弹层开启后背后控件不响应。 |

### 4.3 条件入口与空态

- 有首胜选择奖励：共享等级条后插入“首胜奖励 · 选择武将升星”入口，高88；下方固定筛选/排序整体下移，列表视口相应缩小，不覆盖卡片。可进入现有三选一流程，选中后领取，成功才消失。不得与“首次获得0星”混淆。
- 当前阵营为空：展示“尚未拥有蜀国武将”等准确文案，以及“查看全部”“前往召唤”两个≥88高按钮；资源不足也可进入召唤页了解，不在这里自动消费。
- 全部为空：显示“尚未获得武将”与前往召唤；不补造关羽。对于数据损坏只展示可恢复错误，不能清空真实存档。
- 图片加载中/失败：卡框、姓名、品质、星级照常可用，显示身份占位；失败后允许受控重试，不无限每帧请求。过滤后缺图不能被误作未拥有。

## 5. 武将详情：关羽完整示例

详情是子页，无五标签底栏。固定返回头与固定行动栏，中间为单一纵向 ScrollView。立绘和面板在同一滚动内容中，短屏可以卷走立绘继续看技能；不在小屏上压缩整页文字以假装无需滚动。

### 5.1 基准布局

头部 `0/0/750/88`：返回图标视觉48，热区88×88；标题“武将详情”；右侧只读资源。返回箭头必须有“返回”可理解标签或辅助名称。底部行动区 `0/1180/750/154`：调整编队按钮 `110/1188/530/88`，其下“返回群英录”次级入口；两个热区不能重叠。如果次级返回不能取得独立88高热区，则移到滚动内容末尾，不压成不可用小字链接。

**默认采用行动区仅一个主按钮**：调整编队按钮居中且高88，区内剩余高度为内边距；“返回群英录”放滚动内容最后一行，高88。顶部返回已提供随时离开的固定入口。这样保留样稿的功能，又不通过重叠热区凑触摸规格。

中间可视区 `0/88/750/1092`。以下是内容内坐标，横向边距24；内容总高超过视口时自然滚动。

| 模块 | 内容内 y / h | 规格 |
|---|---|---|
| 关羽画卷 | `0 / 540` | 城关低对比背景独立；关羽主体靠中右，不与左侧姓名身份区重叠；主要面部应在画卷上半部。人物保持比例，武器/衣角可溢出装饰区但受画卷Mask限制。 |
| 身份叠层 | 画卷内左24、上24，宽210 | “武圣”→“关羽”→“蜀 · 武将”→SSR徽→当前星/上限。文字不烘焙进人物图。长称号与姓名允许增宽/换行，由布局管理，不缩至小字。 |

## 6. 适配、状态与反馈

当前 Cocos `CocosBootstrap.ts` 仍设置720×1280；本文750×1334是设计标尺，**不代表项目已切换分辨率**。实现可将设计单位统一乘720/750后映射到引擎节点，并按实际可见高度重新计算视口；不得只改全局分辨率导致其他页面布局失效。安全区由平台适配/引擎信息统一提供，页面不直连 `wx/tt`。

- 常规375/390宽：在阅读字号不下降的情况下适配内容；窄屏320宽可减少左右边距与装饰，三列卡片保持，身份文本布局可调整；若最小可读字号/触摸不达标，应以视口方案重新评审，不能偷偷缩放整页。
- 所有按钮至少44×44逻辑px；在750设计宽下至少88×88。图标可小于热区，但相邻热区必须互不重叠。数组排序按钮、卡片、模态关闭、返回与底栏均适用。
- 点击反馈：按下亮度/缩放轻微变化（建议0.98～1.00），松开触发；列表拖动取消按压，禁用态除颜色变灰还给说明。具体动画时长为建议120～180ms，不属于玩法计时。
- 过渡不超过可感知的短淡入，减少动态效果设置启用时取消位移/弹跳；不以无限发光、漂浮红点吸引付费。奖励入口只在真实可领取时显示。
- 模态期间屏蔽全部底层触摸，关闭后恢复焦点/滚动。加载图像失败不能阻塞返回；发起状态修改期间防双击，成功回调后恢复。
- 一般文字目标对比度4.5:1，大号文字和关键轮廓目标3:1；这些是设计验收目标，现样稿颜色未做自动对比度验证。边框复杂背景上可增加深底，不靠描金细线解决文字可读性。
- 头像和立绘不得整图非等比缩放；不同角色通过元数据调整裁切点。卡片框保持厚度，九宫格边角不可拉花。小图标在32/44逻辑px实看，模糊时简化轮廓而非一味锐化。
